>
> **왜 repo 에 있나** — 메모리는 레포별·PC별이라 안 따라온다. **git 커밋된 파일만** 모든 세션·PC 에

> ⚠️ `.md` 는 dev 전용이다(master 머지 시 제외) — 이 문서는 **dev 브랜치에만** 있다.
> ⚠️ ssancar 축의 짝 = `docs/integration/ssancar-portal-collab.md`. 구조를 일부러 같게 뒀다.

## 2. 기록 규칙 — 세션끼리 대화로 정한 것은 어디로 가나

> 🗣️ **2026-09-17 부터 두 세션은 `SendMessage` 로 직접 조율한다**(jin 지시, 양쪽 `CLAUDE.md` 에 박제).
> **대화는 휘발된다** — 창을 닫으면 사라지고 메모리는 다른 PC 로 안 따라온다. 그래서 아래처럼 나눈다.

| 무엇 | 어디에 | 누가 |
|---|---|---|
| **연동 스펙 변경**(엔드포인트·필드·type·멱등키) | 위 표의 **권위 파일**에 반영 | 각자 자기 레포에서 |
| **결정된 것**(무엇을 왜 그렇게 정했나 · 배포 순서 · 안 하기로 한 것) | 이 문서 **§3 에 날짜 한 줄**로 append | car-erp 세션 |
| **긴 스펙·재개 절차** | 주제별 문서(위 지도) | 그 주제를 가진 쪽 |
| 상대 레포 관련 결정 | **상대 레포**에 상대 세션이 커밋 | 🚫 내가 그쪽 파일을 직접 안 건드린다 |

**🚫 하지 않는 것**
- 대화 전문을 붙여 넣지 않는다(읽히지 않는다). **결론과 근거만.**
- 스펙을 여기 복사하지 않는다 — §1 지도를 가리킨다.
- 「합의했다」를 결정으로 적지 않는다 — **결정은 jin 승인**이다(아래).

**✅ 반드시 남기는 것 — 「안 하기로 한 것」.** 두 세션이 검토하고 접은 안은 기록이 없으면
몇 주 뒤 **다시 제안된다**. 접은 이유를 한 줄로 남긴다.

## 4. 재개 절차 (새 세션에서)

1. 이 문서 §1·§3 을 읽는다. 진행 중 안건은 §3 상단에 있다.
2. `ListAgents` 로 board 세션이 **online 인지** 확인한다 — offline 이면 메시지가 **안 간다**.
   jin 이 그 창을 다시 띄워야 한다.
3. 보낼 이유가 「상대가 뭔가를 실제로 바꿔야 할 때」인지 확인한다(스펙 변경·배포 순서·실측 요청/회신·
   차단 해제). 🚫 판단 확인·인사는 보내지 않는다(jin 2026-09-14 — *「너네 둘이 쓸데없이 토큰 계속
   먹고 있는데」*).
4. 스펙을 고쳐야 하면 **권위 파일**을 고친다(§1). 결정이 생기면 **§3 에 한 줄** 추가한다.
5. 배포는 **jin 명시 승인** — 두 세션이 합의해도 그것만으로 확정하지 않는다.

## 5. 함정 (실제로 밟은 것)

- ⚠️ **board 운영이 구버전일 수 있다** — 구 신호(`purchase_payment`)를 계속 수신해 둔 이유가 그것이다
  (튕기면 유일한 경로가 죽는다). 값을 폐기할 땐 **「받는 목록」에서만 빼고 「그리는 목록」엔 남긴다**
  (SKILLS §8 #59).
- ⚠️ **멱등키가 `(vehicle_id, type)`** 이라, 기존 type 에 플래그를 얹으면 그 차에 같은 type 이 열려 있을 때
  `already_open` 으로 **조용히 버려진다**. 새 신호는 **별개 type** 으로 만든다.
- ⚠️ **세션 없는 경로(연동 API)의 감사로그는 행위자가 빈다** — `AuditLog::actingAs()` 로 감싼다
  (SKILLS §8 #56).
- ⚠️ **board 가 「ERP 에 필요할 것」이라고 보내온 지점은 추정일 수 있다** — 우리 코드에서 **직접 확인**하고
  회신할 때 「확인했다」와 「그럴 것 같다」를 구분한다. **두 세션이 동의해도 둘 다 틀릴 수 있다**
  (실사고: 미수 구성을 ERP 3항 / ssancar 4항으로 주장했으나 실제 8항 — SKILLS §8 #64).
