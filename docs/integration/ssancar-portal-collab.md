## 3. 이 ERP 가 해야 할 일

08 문서 §3 이 정본이다. 요점만:

- **방향 = 단방향.** 사이트가 ERP 를 호출한다. **웹 → ERP 쓰기 없음.** 외부 트리거(포털에서 메일 발송 등)도 금지.
- **인증 = HMAC 읽기 API**(DB 직접 접속 아님). 시크릿은 **출처별로 따로** 발급하고 board 것과도 분리.
- **주기 = 6시간**(JIN 2026-08-24, 구 15분에서 변경 — 해외 송금 확인이 며칠 걸려 분 단위로 볼 값이 없다).
  매 주기 **전체 목록 → 차집합 정리**. 삭제는 **소프트(`is_active`)**. 응답에 `as_of`.
  🚫 **증분(`updated_since`)을 만들지 말 것** — 툼스톤이 없어 **삭제를 영원히 못 잡는다**.
- **다중 출처 = B안(출처별 독립 호출).** 통합 엔드포인트는 **성립하지 않는다**(별도 서버 2대·별도 법인).
  ```
  GET https://heysellcar.com/api/internal/portal/vehicles  → heymanerp 전체
  GET https://heymancar.com/api/internal/portal/vehicles   → ssancarerp 전체
  ```
  가드 = 출처별 `total_count` + `complete` 플래그. `complete:false` 면 사이트가 차집합 정리를 **보류**.
- **Phase 1 원천은 `heymanerp` 뿐.** ssancarerp 는 실데이터 적재 후 Phase 7.

### 🚨 구현 시 반드시 지킬 것 (이번 조사에서 확정)

1. **바이어 predicate = `vehicles.buyer_id` 단일 칸.** `buyer_id IS NULL` 이면 **어느 바이어에게도 발행하지 않는다**
   (= `buyer_undecided`, 바이어 미정 투기 매입).
   > 🚨 **정정 2026-08-24** — 이 자리에 원래 *"`effective_buyer` 단일 출처를 ERP 가 만든다"* 고 적혀 있었다.
   > **그런 것은 코드에 없고(전수 grep 0건), 만들 필요도 없다.** 컨사이니(`effective_consignee`)에서
   > 유추해 이름부터 정해 버린 것이다. 회신 v1 `C-1`·회신 v2 에도 같은 이름이 남아 있으니 그것도 제안으로 읽을 것.

   **실측 근거(heymanerp 전수, 2026-08-24)** — `export_buyer_id ≠ buyer_id` **0건** ·
   `bl_buyer_id ≠ buyer_id` **0건** · `buyer_id` 없이 단계 칸에만 값 **0건** · `buyer_id` 없음 **0건**.
   판매 탭에서 바이어를 고르면 서버가 3칸을 같이 채우고(`vehicles/index.blade.php:2502` `inheritParties()`),
   통관·선적 탭의 바이어 칸은 **읽기 전용 표시**다(2026-07-09 「당사자 축소」).

   🚫 **서류용 폴백을 predicate 로 쓰지 말 것** — `DocValue::invoiceBuyer`(`app/Services/Documents/DocValue.php:32`)는
   `exportBuyer ?: blBuyer ?: buyer` 순으로 **입력 방향과 정반대**다. 갈리는 순간
   **포털에 보이는 이름과 손에 든 인보이스의 이름이 달라진다.**

   🔒 **가드 테스트가 선행 개발 1건이다.** 불일치 0 은 자동전파가 지켜주는 것이지 스키마 보장이 아니다.
   ERP 에는 정확히 그 가정이 깨진 사고 이력이 있다(`SKILLS.md §8 #38` — 컨사이니 입력칸을 옮기고 읽는 쪽 4곳을
   안 옮겨 화면이 통째로 빈값). 바이어에서 같은 일이 나면 **에러 없이 남의 차가 남의 포털에 뜬다.**

   ⚠️ **축이 바뀐다.** 기존 board API 는 **영업(`salesman_id`) 스코프**이고 바이어는 단순 표시값이다.
   포털은 **바이어가 인가 축**이라 이 predicate 가 곧 **IDOR 경계**가 된다 — 서버가 강제 필터할 것.
2. **명시 allow-list projection 만.** `purchase_seller_account`·`nice_reg_owner_rrn`·`consignees.id_value` 는
   `encrypted` cast 라 **속성 접근 시 자동 복호화**된다. `toArray()` 한 번이면 평문으로 나간다.
   🚫 `except()` 블랙리스트 금지. `Vehicle::portalMeta()` + 명시 `map()` 패턴을 쓸 것.
3. **기존 board 읽기 API 를 그대로 재사용하지 말 것.** 그건 **직원(영업) 대면**이고
   `GET /internal/board/buyers` 는 `purchase_lock.basis`·`unsecured_limit_krw`·`unpaid_ratio_pct` 를 내려준다
   — **그 바이어에 대한 내부 신용 판단**이다. 재사용할 것은 **응답이 아니라 골격**
   (HMAC 미들웨어 + named throttle + allow-list projection + 스코프 base 쿼리 1개).
4. **감사 로그는 재사용 가능.** `document_access_logs` 가 이미 `source`·`actor_email` 을 갖고
   `user_id` 가 nullable 이다(board 유저용). `source='buyer_portal'` 로 그대로 쓸 수 있다.
5. **🚫 바이어에게 절대 나가면 안 되는 것** — 매입가·매도비·비용 13종·마진·정산 **전면 제외** /
   주민등록번호·원 소유자 성명·주소(**`nice_reg_owner_name`·`addr` 는 평문이다**)·매입처 계좌·여권번호 /
   `buyers.unsecured_limit_krw`·`lock_*_pct`·`memo` / 탭별 메모 5칸(**`memo_sale` 포함**) /
   말소등록증·위임장·통관 SET(국내 소유자 PII 인쇄됨).

### 4-2. 🚨 약속은 있는데 코드가 없다 — 이게 1순위 안건

**화면을 잘 그려도 채울 숫자가 안 생긴다.**

- **성공파트너**: "차를 사면 자동 적립" → 원장 INSERT 는 CLI 하나, cron 0건 /
  "FOB 의 0.3~1.0%" → **차량 데이터에 가격 필드 자체가 없다** /
  "18개월 만료·90일 전 알림" → 집행 배치 0건 / 약관 §3.3 "+0.10%p" → 정책 파일이 *"가산 상수는 두지 않았다"* 고 명시
- **싼카파트너스**: 콘텐츠 보상 파이프라인은 **크론 2개로 제대로 구현됨**. 그러나
  문의 $3 = 전부 없음 / 거래 $50~200 = 관리자 수기 별도 트랙(원장·배치에 안 들어감) /
  재구매 50%·30일 클로백 = 컬럼만 / 등급 자동승급·분기 유지심사 = **판정 코드 자체가 없음** /
  팔로워 재인증 UI 없음 → `verified_reach` 영원히 0 → **전원 starter 고정**(요율도 최저 고정)
- **NAS 「적립금 내역」은 성공파트너 원장이 아니다** — 선수금·과오납 크레딧 원장이고
  사용처의 대부분이 **운임 상계**다. 바이어 간 이전도 97건 있다. 성공파트너 원장은 **어디에도 없다.**

### 4-5. 과거 거래 이력은 2021년부터 쓸 수 있다

전 연도 고유 차량 **12,950대**, 현행 ERP(2024-03~) 범위 밖 **8,338대**.

## 7. 세션 재개 절차

1. **이 문서**를 읽는다 (지금 하고 있는 것).
2. **`연구소\ERP_SSANCAR_WEB\` 에서 가장 높은 버전의 `ERP_연동_통합정리_v1.N.md` 를 읽는다.** ← 여기가 정본이다.
   그 문서 **§0 에 버전 규칙**이 있다 — 양측이 번갈아 쓰고, **다음 차례면 직전 버전을 복사해 번호를 올린 새 파일**에 쓴다.
   **기존 파일은 지우지 않고, 남의 판단도 지우지 않는다**(반박은 원문 아래에 근거와 함께 덧붙인다).
3. 필요하면 `12_바이어_마이페이지_설계_협의.md`(화면 설계 원본) · `08_..._v1.0.md`(연동 스펙, §5 정정 이력 먼저)를 본다.
4. **ssancar.com 코드를 봐야 하면** `C:\xampp\htdocs\ssancar\htdocs` +
   그 레포의 `CLAUDE.md`(운영 동기화 절차)를 먼저 읽는다.
5. 조사·초안은 서브에이전트로 나눠도 되지만 **파일 write·git 은 main 이 단독**으로 한다
