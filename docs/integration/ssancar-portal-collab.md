## 0. 한 줄 요약

**SSANCAR 대표가 「회사 웹사이트(ssancar.com) 회원 마이페이지를 만들어 달라」고 요청했고,
그 화면을 채울 데이터의 상당 부분이 이 ERP 에 있다.** 두 레포를 오가며 진행한다.

- **car-erp** (이 레포) = 데이터 공급자. 읽기 API 를 열어 준다.
- **ssancar.com** = 화면. 받은 데이터를 저장·표시만 한다.
- 관통 원칙: **ERP 가 계산해서 발행하고, 사이트는 저장·표시만 한다.** 상세 = 바로 아래 「관통 원칙」 — 🚫 **계산·문서대조·면책문구 전부 안 한다.**

## 🔑 관통 원칙 (jin 2026-08-25 — **이거부터 읽을 것**)

> *"바이어 정보는 ERP DB에서 그냥 보여줄 뿐이야. 무슨 문서를 다운받고, 뭘 계산하고 하지마.
> 그냥 ERP에서 보는 거 그대로 보여주면 돼. 차 40유로가 미수금으로 남았어? 그거 그대로 보여줘.
> 그럼 적립금에서 까달라고 하거나 뭐라도 요청하겠지. 다음에 입금한다거나."*

```
포털 = ERP 화면을 그대로 비추는 창
🚫 사이트가 계산하지 않는다   🚫 다른 서류와 대조하지 않는다   🚫 면책·해명 문구를 붙이지 않는다
```

**값이 이상해 보이면 화면이 설명하는 게 아니다.** 바이어가 보고 *"적립금에서 까주세요"*·
*"다음에 입금할게요"* 라고 **요청하는 것**, 실무자가 **ERP 에서 고치는 것** — 그게 목적이다.
화면에 설명을 붙이면 그 흐름이 막힌다.

### ⚠️ 실제로 여기서 한 번 새어나갔다 (2026-08-25)

ERP 가 v1.12 §18-5 에 *"포털 잔금이 판매계약서 Balance 와 다를 수 있다"* 를 **주의로 한 줄** 적었다.
ssancar 가 그걸 질문(Q18 — *"화면에 뭐라고 쓸까"*)으로 받았고, ERP 는 거기에 실측까지 붙여
**「계약서가 과다 청구한다」** 로 키웠다. jin 이 끊었다 — *"그냥 정보를 보여주는 건데 뭔 판매계약서야."*

**무엇이 빠졌었나**: 판매계약서는 **판매 시점에 한 번 뽑는 서류**다. 그 시점엔 회수이력이 없다
(운임 입금은 나중에 들어온다) — **옛 계약서를 다시 뽑아 보내지 않는 한 갈릴 일이 실무에 없다.**
**발생 경로를 못 쓰면 그건 위험이 아니라 가정이다.** 주의를 적기 전에 그 경로를 먼저 써 볼 것.

🔬 실측이 결론을 굳혔다 — 계약서와 갈리는 18대는 `write_off` **0건** · `offset` **0건**,
나머지는 「운임 입금 6/30」·「원화로 입금됨」·「[CD-FIX] 정산 정리」로 **전부 바이어가 보낸 돈**이다.
**감출 것도, 설명할 것도 없었다.**

### 🚫 바이어에게 안 나가는 것 — **신용도·한도·게이트** (jin 2026-08-26)

> *"바이어 신용도 보이는 건 보여주지 말자. 그건 내부적으로만 확인하자.
> 추후 변동이 생기면 그때 열어주면 되니까."*

**발행도 안 하고, 화면에 자리도 만들지 않는다.**
🔑 「데이터가 없어서 지금은 못 한다」가 **아니다** — 그렇게 읽으면 데이터가 채워지는 날
자동으로 열리는 걸로 오해한다. **판단이 끝났고, 열려면 jin 이 다시 연다.**

**대상**: `BuyerCreditScore`(score·grade·recommended) · 매입 여력 게이지 20칸
(`Buyer::computeReceivableGauge` — `available_krw`·`limit_krw`·`deposit_pct` 등) ·
바이어별 게이트(`lock_*_pct`) · 무담보 한도(`unsecured_limit_krw`).

⚠️ **왜 게이지가 애초에 바이어 값이 아닌가** — `used_krw` = 우리가 **매입처에** 지급한 돈,
`available_krw` = **우리가 이 바이어에게 얼마나 더 매입해 줄 것인가**.
**바이어 잔액이 아니라 SSANCAR 의 자본 노출**이다. 게다가 전부 `_krw` 라 통화도 안 맞는다.

🔒 가드 = `PortalVehicleApiTest::test_forbidden_values_never_appear_in_the_payload`.
⚠️ **다만 나중에 「바이어 단위」 엔드포인트를 새로 만들면 이 결정이 자동으로 안 따라온다** —
그때 화이트리스트를 **처음부터 다시** 세울 것.

📌 곁다리 — `deposit_pct` 는 **설정값이 아니라 파생값**이다:
`(100 − 매입등록 필요입금률)/100 × 100`. heymanerp 60% → `40`.
**매입 게이트를 조이면 매입 여력 비율이 같이 움직인다.** 어딘가에서 이 값을 쓸 일이 생기면 기억할 것.

## 3. 이 ERP 가 해야 할 일

08 문서 §3 이 정본이다. 요점만:

- **방향 = 단방향.** 사이트가 ERP 를 호출한다. **웹 → ERP 쓰기 없음.** 외부 트리거(포털에서 메일 발송 등)도 금지.
- **인증 = HMAC 읽기 API**(DB 직접 접속 아님). 시크릿은 **출처별로 따로** 발급하고 board 것과도 분리.

| 집으려던 것 | 실제로 세는 것 |
|---|---|
