# 챗봇 색인 세션 인계 — 권한별 RAG 청크 격리

> 작성: 2026-07-29 car-erp 세션  
> 대상: Notion 챗봇 카드·가이드 색인을 생성하고 3사 ERP에 배포하는 세션

## 목적

하나의 ERP 챗봇을 그대로 사용하되 로그인 계정에 따라 검색 가능한 자료를 서버에서 격리한다.

- 실무자: 업무 절차와 허용된 운영 자료
- 재무·관리: 채권·미수·정산 자료
- 대표: 자금현황·청산가치·손익분기
- 시스템관리자: 기능설정·알림톡 로그·Ollama/색인·시스템 운영

> ⚠️ **인원별 매출은 등급이 아니라 스코프다 (jin 2026-07-29 정정).**
> 대표 전용이 아니다. **최고관리자·업무관리자 = 전사 / [관리] = 본인이 담당하는 영업만 / 재무·수출통관·영업 = 거부**(매출은 관리 라인만).
> 숫자는 전부 DB 조회라 색인 등급과 무관하지만, **용어·사용법 카드를 만든다면 `finance`** 에 둔다(executive 아님).

질문 문구나 LLM 판단으로 권한을 정하지 않는다. 로그인한 `User`의 권한으로 청크를 먼저 제거한 뒤 임베딩 유사도를 계산한다.

## car-erp가 요구하는 색인 계약

`storage/app/index-erp.json`은 아래 객체의 배열이다.

```json
{
  "source": "사내 업무 가이드 › 🏢 ERP (car-erp) › 대표 전용 › 자금 현황",
  "text": "자금 현황 설명...",
  "embedding": [0.01, -0.02],
  "audience": "executive"
}
```

허용 등급은 정확히 네 가지다.

| audience | 접근 계정 |
|---|---|
| `staff` | 챗봇 사용이 허용된 모든 계정 |
| `finance` | 재무·관리·업무관리자·대표·시스템관리자 |
| `executive` | 대표(`admin`)·시스템관리자(`super`) |
| `system` | 시스템관리자(`super`)만 |

- 색인 전체에 `audience`가 하나도 없는 현재 구 형식만 하위 호환을 위해 전부 `staff`로 처리한다.
- 청크 하나라도 `audience`를 가지는 새 형식에서는 미표기 청크를 전 계정 검색에서 제외한다. 따라서 새 색인은 모든 청크에 등급을 넣어야 한다.
- 알 수 없는 값은 car-erp가 검색에서 제외한다(fail-closed).
- 배열도 지원하지만 새 색인은 혼선을 줄이기 위해 단일 문자열을 권장한다.
- `audience` 필터는 임베딩 검색과 LLM 호출 전에 적용된다. 허용되지 않은 원문은 LLM 프롬프트에 들어가지 않는다.

구현 위치:

- `app/Models/User.php` — `assistantAudiences()`
- `app/Services/Assistant/AssistantService.php` — `guide()`의 선필터

## Notion → audience 매핑

페이지 제목의 단어를 추측하지 말고, 페이지 ID 또는 명시적 마커를 단일 출처로 사용한다.

권장 방식:

1. 권한별 부모 페이지를 만든다.
   - `실무 가이드` → `staff`
   - `재무·관리 전용` → `finance`
   - `🔒 대표 전용` → `executive`
   - `🔒 시스템관리자 전용` → `system`
2. 색인기 설정에 부모 페이지 ID → audience 매핑을 둔다.
3. 하위 페이지와 카드 청크는 가장 가까운 권한 부모의 audience를 상속한다.
4. 권한 부모를 찾지 못한 새 페이지는 자동 배포하지 말고 경고 목록에 남긴다.

페이지 ID 매핑이 어려우면 각 페이지 첫 블록에 `ASSISTANT_AUDIENCE=executive` 같은 기계 판독용 마커를 넣고, 색인 본문에서는 해당 마커를 제거한다. 제목 문자열 추론만으로 등급을 정하는 방식은 제목 변경 시 정보 노출 위험이 있어 금지한다.

## 대표 전용(`executive`) 카드 — 2장뿐

1. `손익분기`
   - 기준: 청산가치 = 투입원금
   - 초과/부족 금액은 최신 자금 스냅샷으로 계산
2. `청산가치`
   - 통장현금 + 재고 + 경매보증금 − 미지급 − 가수금

> ⚠️ **`자금 현황 입력`·`예치·가수금` 카드는 `executive` 가 아니라 `finance` 다** (2026-07-29 정정).
> 그 화면(`/erp/deposits`)의 실제 가드는 `canEnterCashBalance()` = super·admin·업무관리자 +
> role 재무·관리이지 `canViewCapital()`(super/admin)이 아니다. 카드 본문의
> "누가: 재무·관리·업무관리자"가 코드와 일치한다.
> **경계**: 자금현황 *숫자*(청산가치·손익)는 대표 전용(`capital_status` 가 DB 에서 하드 거부) /
> 그 화면을 *어떻게 쓰는지* 안내는 재무·관리도 봐야 한다. 카드는 후자다.
> 숫자는 색인이 아니라 DB 에서 나오므로 등급을 낮춰도 금액이 새지 않는다.

> ❌ **`회사 손익·인원별 기여` 카드는 만들지 않는다** (2026-07-29 폐기).
> 손익은 위 `손익분기`·`청산가치` 가 이미 커버하고, 인원별 기여는 인원별 매출인데 그건
> **등급이 아니라 스코프**(최고관리자·업무관리자=전사 / [관리]=본인 담당 / 재무·수출통관=거부)다.
> 대표 전용 카드로 만들면 등급을 잘못 박는 셈이다.

시스템관리자 전용 카드는 `system` 영역에만 둔다.

- 기능설정
- 알림톡 로그·알림톡 안내
- Ollama/색인 동기화
- 서버·연동 장애 확인 절차

실무 카드에는 대표·시스템관리자 화면의 경로·수치·운영법을 중복 기재하지 않는다.

## DB 조회와 RAG의 역할 분리

다음 질문은 RAG 문서를 읽어 숫자를 답하지 않는다. car-erp가 DB에서 직접 계산한다.

- 자금현황·청산가치·손익 → `capital_status` (대표 전용, 그 외 거부)
- 손익분기 → `break_even` (대표 전용, 그 외 거부)
- 인원별 매출 → `sales_by_salesman` (**관리 라인 전용 + 스코프** — 위 ⚠️ 참조)
- 인원별/바이어별 미수·채권 요약 → 기존 재무 조회

색인은 용어·산식·사용법 설명용이다. 실제 금액은 색인에 박지 않는다.

## 안전한 적용 순서

현재 운영 색인은 민감 카드가 제거된 안전한 상태다. 아래 순서를 바꾸지 않는다.

1. 이 권한 필터가 포함된 car-erp 코드를 테스트·배포한다.
2. 색인기에 `audience` 생성 로직과 미매핑 페이지 경고를 넣는다.
3. 샘플 색인을 만들고 네 계정 유형별 검색 격리 테스트를 한다.
4. 그 다음에만 대표·시스템관리자 전용 Notion 카드/가이드를 발행한다.
5. 전체 재색인 후 ERP 3사 `storage/app/index-erp.json`에 배포한다.
6. 서버별 파일 mtime·청크 수·audience별 수를 검증한다.
7. 모든 청크에 audience가 있음을 확인한 뒤 3사 `.env`의 `ASSISTANT_STAFF_ENABLED=true`를 설정한다.

권한 필터 코드가 운영 배포되기 전에 민감 카드가 든 색인을 먼저 배포하면 안 된다.
`ASSISTANT_STAFF_ENABLED`의 기본값은 false라서 새 색인 준비 전에는 기존처럼 재무·관리 tier만 챗봇이 보인다.

|---|---|---|---|---|---|
| 정산은 누가 확정해? | 실무 가이드 답변 | 답변 | 답변 | 답변 | 답변 |

| 이번 달 인원별 매출 | **거부** | **본인 담당 영업만** | **전사** | 전사 | 전사 |
| 기능설정 어디서 해? | 거부 | 거부 | 거부 | 거부 | system 가이드 |

추가 검증:

- 재무 계정의 RAG `sources`에 `executive`·`system` 청크가 0개
- 대표 계정의 `sources`에 `system` 청크가 0개
- 알 수 없는 audience 청크가 모든 계정에서 0개
- 거부 질의가 `AuditLog.column_name=<intent>(denied)`로 기록
- `php artisan test tests/Feature/AssistantTest.php` 통과

## 이번 car-erp 세션에서 구현된 내용

- `sales_by_salesman`, `break_even` 의도 추가
- 자금·손익에 대표 권한 게이트 적용(그 외 하드 거부)
- 인원별 매출은 관리 라인 전용 + `User::getSubordinateSalesmanIds()` 스코프(차량·바이어·재고·export 와 같은 단일출처)
- 채권 조회도 서비스 내부에서 재무 등급을 재검사
- 시스템 운영 질문 `system_guide`를 super 전용으로 분리
- RAG 청크 audience 선필터 및 잘못된 등급 fail-closed
- 권한·감사로그·색인 격리 회귀 테스트 추가

운영 배포와 대표/시스템관리자 전용 Notion 카드 재발행은 이 인계장의 안전한 적용 순서에 맞춰 별도 진행한다.
