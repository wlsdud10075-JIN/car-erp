# 전역 지침 (모든 프로젝트·세션 공통)

## 언어 — 항상 한국어

사용자에게 보이는 **모든 응답 텍스트를 한국어로** 작성한다. 여기에는 도구 사용 사이의 **상태·진행·내레이션 줄**("이제 X를 확인하겠습니다", "Let me check Y" 류)도 **전부 포함**된다. 기술 작업에 깊이 들어가더라도 영어로 새지 말 것.

**예외(관례 유지 — 한글로 바꾸지 말 것)**:
- 코드·설정 파일 내용
- git 커밋 메시지·PR 제목/본문 (해당 레포 관례를 따름)
- 기술 식별자(변수·함수·클래스·테이블·컬럼명), 파일 경로, 명령어·플래그 문법
- 로그·에러 메시지 원문 인용

즉 **사람에게 말하는 산문은 한국어, 기계가 읽는 것/식별자는 원문 그대로.**

## Codex 위임 — Claude가 굳이 안 해도 되는 잡일 (토큰 절약)

Notion 발행·정리처럼 **Claude의 코드·판단 강점이 굳이 필요 없는** 실행형 반복 작업(특히 토큰을 많이 먹는 것)은 **Claude가 직접 실행하지 말고 Codex에게 위임**한다. 목적 = Anthropic 토큰 절약.

- **위임 방식**: Claude 는 그 작업의 **전달 패킷**(무엇을·어떻게 + 실행 명령 + 검증 + 인계문서 경로)을 만들어 **사용자에게 전달**한다. 사용자가 그걸 **Codex 세션에 붙여넣어** 실행시킨다. (Claude 가 상대 세션에 직접 통신하는 채널은 없음.)
- **Codex 실행 환경**: Codex 는 항상 `C:\xampp\htdocs` 에서 시작한다. 인계문서는 이 경로 기준으로 참조.
- **Notion 작업 정본 인계문서 = `C:\xampp\htdocs\CODEX_NOTION_HANDOFF.md`** — Codex 가 이걸 읽고 수행. 사용자는 "그 문서 보고 해줘"라고 지시. 새 유형의 반복 위임이 생기면 같은 식으로 `C:\xampp\htdocs\CODEX_*_HANDOFF.md` 를 추가.
- **위임 대상 예**: Notion 가이드 발행/허브 네비 정리, 단순 반복 스크립트 실행, 대량 웹 조사·긴 문서 요약 등 "판단보다 실행 비중이 큰" 일.
- **Claude 가 직접 하는 것**: 코드 작성·디버깅·마이그레이션·배포, 레포 맥락/설계 판단이 필요한 일.
- 위임형 작업 요청이 오면 **기본적으로 Codex 전달 패킷을 준비**하되(직접 실행 X), 사용자가 "지금 네가 직접 해"라고 하면 그때 직접 수행. 위임 여부가 애매하면 사용자에게 확인.

## 오케스트레이터 팬아웃 작업방식 (jin 선호 2026-07-13 — 전 프로젝트 공통)

여러 갈래로 갈라지는 작업, 또는 사용자가 대화 중 다른 작업을 계속 끼워넣을 때의 기본 작업 형태. **claude agents 를 개별 세션으로 굴려 서로 조율시키는 방식(맥락 없이 막 함 → 취합 난망)의 상위호환.**

- **Claude=main 이 사용자와 계속 대화**하며 무엇을 할지 결정한다. main 이 실행에 안 막혀 있어야 사용자가 언제든 다음 안건을 끼워넣을 수 있다.
- 확정된 **독립적인**(서로 안 얽힌) 조각은 **서브에이전트(Agent 툴, 백그라운드)**에 **정밀 패킷**(무엇을·정확히 어느 파일·어떤 형식으로 반환)으로 지시한다. 서브에이전트끼리 서로 몰라도 됨 — **겹치지 않게 쪼개고, 공유 맥락 보유·취합은 main 이 단독**으로 한다.
- 서브에이전트는 **조사·초안·dry-run 까지만**. **실제 파일/워킹트리·git 은 main 이 단독으로 write**(서브에이전트는 커밋·푸시 금지). 이게 안전의 핵심 — 실배포 경로에 손대는 건 main 하나뿐.
- main 이 결과를 취합·검증한 뒤, **사용자에게 "이렇게 됐고 이렇게 합칠게" 보고 → 사용자 "진행해줘" 승인 후에만 실제 반영**한다.
- **작거나 서로 얽힌(앞 결과를 봐야 다음이 정해지는) 일은 스폰하지 말고 main 이 인라인 처리** — 스폰할지/직접 할지는 매 건 main 이 판단해서 알린다.
- 대량 병렬 잡을 명시 요청 없이 남발하지 말 것. 독립성이 확실하고 이득이 있을 때만.
- ⚠️ 같은 레포를 여러 서브에이전트가 **동시에 편집**해야 하면 worktree 격리(각자 독립 사본) 필수. 대개는 읽기·조사·초안으로 쪼개면 격리조차 불필요.
