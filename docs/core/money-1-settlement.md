## 💰 돈 ① 정산 (코드 대조 2026-11-20 — `app/Models/Settlement.php`)

> 숫자(50% · 10만 · 20만 · 25% · 1억 · 100만 · 5만 · 9% · 10%)는 **코드 기본값**이다. 실제 값은 기능설정의 정산 파라미터(`Settlement::param()`, 키 `settlement_*`)가 정본 — 회사가 바꿔 놨을 수 있다. 🚫 숫자를 코드·화면에 새로 박지 않는다.
> 🚫 등급·공식을 다른 곳에 옮겨 적지 않는다 — 화면 미리보기·자동 기입·정산액이 전부 아래 함수를 부른다.

### 1. 수출 차량 (ssancarerp · heymanerp)
```
판매금원화     = (sale_price + commission + auto_loading − tax_dc) × 정산환율     ← 정산환율 = settlementRate() (돈 ② 환차)
정산판매금원화 = 판매금원화 − cost_total
판매마진       = 정산판매금원화 − (purchase_price + selling_fee)
부가세마진     = purchase_price × 9%                    ← 매도비 제외
총마진         = (판매마진 + 부가세마진) × (100% − 10%)   ← 부가세 10% 차감
```
- 운임비(`transport_fee`)·기타판매비용(`sale_other_costs`)은 **안 들어간다**(받을 돈에만 들어간다 — 돈 ③ 세 합계).

### 2. 정산액 — 정산 유형(`settlement_type`)으로 갈린다
**비율(`ratio`) — 프리랜서, 그리고 바이어 정산 방식(5:5·7:3)으로 비율을 받는 사내직원**
- 정산액 = 총마진 × 비율. 비율 = `settlement_ratio`(재무 입력·바이어 방식) 없으면 기본 50%.

**건당(`per_unit`) — 사내직원**
- 재무가 `per_unit_amount` 를 직접 넣었으면 그 값. 비어 있으면 자동 등급(`autoPerUnitAmountAt` → `employeePerUnitTier`):

| 순서 | 조건 | 건당액 |
|---|---|---|
| 1 | 판정 마진 < 0 | **0** |
| 2 | 퇴사자에게서 승계한 바이어의 거래(`isInheritedBuyerDeal`) | 5만 |
| 3 | 그 직원의 차등 등급이 꺼져 있음(`salesmen.per_unit_tier_enabled` = false) | 10만 |
| 4 | 매입합계(매입가 + 매도비) ≥ 1억 | 판정 마진 × 25% |
| 5 | 판정 마진 < 100만 | 10만 |
| 6 | 그 외 | 20만 |

- **판정 마진 = 총마진 − 발송비 직원 몫(50%)**. 건당액 자체는 발송비로 깎지 않는다.
- 지급(paid) 때 건당액이 고정된다. 그 뒤 값이 바뀌어 등급이 달라지면 **2차 마감 때 다시 매겨 차액을 이월**한다(재무가 직접 넣은 건당액은 다시 매기지 않는다).

### 3. 실지급액
```
실지급액 = 정산액 − 서류비 − 발송비 차감 − other_deduction + 전월 이월(carryover_in_krw, 음수면 차감)
```
| | 프리랜서(비율) | 바이어 비율로 받는 사내직원 | 사내직원(건당) |
|---|---|---|---|
| 서류비 | 5만 | **0** | 0 |
| 발송비 차감(실지급에서) | 발송비의 50% | 발송비의 50% | 0 (판정 마진에서만 본다) |

- 발송비 = 그 차의 EMS·DHL 실비 합(`Vehicle::shipping_fee_total`). 회사 부담분은 금액 0 으로 기록돼 자동으로 영향이 없다.
- 단일 출처: `getDocumentFeeAttribute` · `shippingFeeDeducted()` · `shippingFeeEmployeeShare()`(끝수는 회사가 진다).

### 4. 내수 정산 (`is_domestic` — 내수 바이어 거래)
```
내수 기준액 = 총판매가 − 매입가 − 말소비 − 탁송비        ← Vehicle::domestic_margin, 이 값이 곧 총마진
```
- 🚫 부가세마진(9%)도 × 0.9 도 **안 탄다**. 환율도 안 탄다(원화 전제). 환차 제외 판정에서도 늘 빠진다.
- 정산액·서류비·실지급액·회사이익은 위 2·3번 규칙을 그대로 탄다(분기는 `total_margin` 한 곳뿐).
- 사내직원(건당): **건당액이 기준액보다 크면 0**(번 돈보다 많이 주지 않는다).
- 마진율은 내수에 없다(null — 0% 로 그리지 않는다, 평균에도 안 넣는다).

### 5. karaba (`Setting::isKaraba()`)
```
영업이익 = sale_price × 판매환율 − (매입가 + 매도비 + cost_total − 매입세액 purchase_vat_amount)
이익률   = 영업이익 ÷ (sale_price × 판매환율)
```
- **프리랜서(비율)**: 정산액 = 영업이익 × 요율, 10원 절사, 영업이익 ≤ 0 이면 0. 요율 = 비율칸 값(>0) 없으면 이익률 구간 — **6% 이상 20 / 5% 이상 15 / 그 밖 10**(`karabaTierPercent`).
- **사내직원(건당)**: 위 2번의 건당 규칙 그대로.
- 판매환율을 쓴다(정산환율·환차 규칙과 무관). 실지급액 식은 3번과 같다.

### 6. 회사이익 (`Settlement::company_net`)
```
회사이익(정산 1건) = 총마진 − 실지급액 − 발송비 전액 + 환차 회사 몫(companyFxKrw — 환차 제외 정산만, 아니면 0)
```
- 식은 유형과 무관하게 같고 **회사가 지는 발송비가 다르다**: 프리랜서·바이어 비율 = 50%(나머지는 실지급에서 이미 빠짐) / 사내직원 건당 = 100%.
- 회사이익을 보여 주는 곳은 **조립이 세 갈래 + 엑셀 수식**이다(월정산 카드·승인 링크·결재 알림톡 / 관리자 대시보드 / 월결산 알림톡 — 표는 돈 ⑤ §9). 정산 1건의 몫은 전부 이 accessor(또는 같은 식)에서 나온다 — **공식을 바꾸면 돈 ⑤ §9 의 표를 줄마다 따라가 다 맞춘다.** 월정산 수동 조정은 배치에 달려 있어 호출부가 따로 더한다.
- 내수직원 월정산이 켜진 회사(기본 ssancarerp만)는 회사 순이익에 `+ 내수직원 「총 회사수익」`(`BatchPayoutBreakdown::domesticProfitForMonth` — 평가사 지급 뒤 값이라 내수 지급합계를 다시 빼지 않는다).
- karaba 는 `display_margin` 이 영업이익이다(화면 라벨도 영업이익).

### 7. 자동으로 채워지는 것 · 고정되는 것
- 거래완료 진입 시 `Vehicle::saved` 가 정산 행을 만들고 정산 유형만 정한다 — **비율·건당 칸은 비워 둔다**(비어 있으면 위 자동 등급으로 계산). 판매 바이어에 정산 비율이 정해져 있으면 그 비율을 박제한다(`ratio_source=buyer`). 🚫 「거래완료 때 50%·10만이 DB 에 채워진다」는 옛 설명이다.
- 지급(paid) 때 그 시점 값이 `confirmed_snapshot` 에 박제된다. 그 뒤 변동은 2차 정산(돈 ④)으로만 반영된다.
- 총마진·정산액·실지급액·회사이익은 `settlements` 에 **저장하지 않고** accessor 가 매번 계산한다(고정되는 것은 지급 때의 `confirmed_snapshot` 뿐).
- 🚫 발송비를 `total_margin` 자체에서 빼지 않는다 — 회사이익·월정산 카드·대시보드가 그 값을 쓰고, 발송비는 실지급(비율)·건당 판정·`company_net` 에서 따로 본다.
- `cost_total` = 비용 **14칸** 합(`Vehicle::getCostTotalAttribute`) — 화면 입력칸 10개(`Vehicle::DISPLAY_COST_FIELDS`: 말소·면허·탁송·캐리·쇼링·보험·이전비·주차료·기타1·기타2) + 입력칸 없는 옛 칸 4개(점검·성능·수리·광고). 「비용 10칸」은 입력칸 수이지 합계의 구성이 아니다.
