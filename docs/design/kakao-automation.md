## 0. 한 줄

실무자 카톡(나 1명 ↔ 상대 N명)에서 **내가 해야 할 일 · 답을 기다리는 일 · 놓쳤을 가능성**을 버튼 한 번에 뽑아 보여주는 **개인용 PC 프로그램**. 읽기도 개인, 보기도 개인. 영상 「클로드+Jev 카톡 비서」의 핵심(메시지 의도 판정)을 **외부 AI 없이, 사내에서** 구현한다.

## 4. 분류 설계

**유형** = 요청 / 질문 / 대답 / 확인(네·넵·감사) / 정보(일정·금액·링크) / 잡담 / 첨부(사진·파일·이모티콘, 분류 제외).
**방향** = 상대→나(내가 할 일) / 나→상대(기다리는 것) / 나와 무관(내가 수신자·발신자가 아닌 것 — 단체방).

**1단계 = 규칙(2번) + 임베딩 분류기(3번)**
- 규칙 = 글자 패턴. 이 회사 실무자는 반쯤 정해진 서식을 쓴다 — 「매입액 : … / 바이어 : … / 계약금: N만원 입금 부탁드립니다」(계약금 송금 요청 + 금액·바이어 추출), 「~부탁드립니다/승인 부탁」=요청, 「~요?/~까요?」=질문, 「넵/알겠습니다/감사합니다」=확인, 「사진/파일: *.pdf」=첨부, 「@이름」=대상, 차량번호 `NN가NNNN` = 어느 차. 한계 = 「배차하셔도 됩니다」(허락), 완곡 요청, 그리고 **해결 연결**은 규칙으로 거의 안 됨.
- 임베딩 분류기 = 문장 → 벡터(bge-m3, CPU 가능·0.7GB) → 작은 분류기(수 MB)로 유형. **학습 데이터 = 무사백-수출팀 내보내기 20,546건**(jin 바탕화면 `KakaoTalk_20261109_1503_03_399_group.txt`, 2025-08-29~2026-11-09) 중 300~500건 라벨(Claude 가 달고 jin/팀장 표본 검수). 장점 = 사내·무료·실시간·우리 말투에 맞춤·수정이 학습이 됨. 한계 = 유형 고르기만(요약·해결 연결·값 추출 ✗), 라벨 필요, 정확도 85~90% 선.
- 「해결됐나」 = 규칙(같은 차량번호·금액의 후속, 요청 뒤 상대의 확인/완료 보고) + 사람이 최종(주 버튼). 자동 판정은 「아마 해결」 표시만.
- 2단계(선택) = 요약·맥락 경고(영상의 「조립 전 중지!」)가 필요해지면 LLM 하나를 붙인다 — 후보: GPU 증설 / 국내 API(HyperCLOVA X·Solar) / 해외 API(Haiku 5.5 건당 ≈0.1원). 외부 전송 여부는 jin 결정 사항(§6).

## 5. 화면 사양 (v4 목업 = 정본)

- 창 하나(폭 ~700px). 제목 「내 카톡 할 일」 · 상태 한 줄 「HH:MM 읽음 · 최근 7일 · 방A 외 N곳 · 방 선택」 · 노란 **[지금 읽기]**. 뜻 못 정한 메시지가 1건이라도 있으면 바로 아래 경고줄 「확인 필요 N — 지금 정하기」.
- 묶음(기본 전부 접힘, 제목 = 건수 + 이름 + 한 줄 뜻 + 「펼치기/접기」):
  1. **놓쳤을 가능성**(연한 빨강) — 마감·재확인 시점 지남 / 「넵」만 하고 처리 확인 없음 / ERP 에 연관 기록 없음 / 며칠째 상태 변화 없음. 확정이 아니라 가능성 → 확인을 청한다.
  2. **지금 할 일** — 들어가는 조건은 **이유**(다른 사람·돈이 막힘 / 시간 민감 / 오늘 마감 / 놓치면 손실). 경과시간만으로는 안 올린다.
  3. **오늘 안에** — 막힌 사람 없음, 단순 전달, 준비물 부족.
  4. **답 기다리는 중** — 내가 상대에게. 각 요청에 「HH:MM까지 기다림」. 지나면 1 로 승격.
  5. **미뤄둔 일** — 「언제까지 미룸 · 사유」. 시점이 오면 2 로 올라온다.
  6~8. 접힘: 오늘 끝난 것(자동 완료 후보 표시) · 확인 필요 · 나와 무관.
- 행 = 동사형 제목 · 누가↔누구 · 시각·방 · 마감/재확인 시점 · **지금 보여주는 이유(알약 1개)** · 핵심값(차량번호·금액, 추출된 것만) · 버튼 **[주 버튼][미루기][⋯]**(차량번호 확실하면 [차량 열기] 추가). 행 본문을 누르면 원문·앞뒤 대화 + [ERP 확인][분류 수정][내 일이 아님].
- [⋯] 목록 = 보기(원문 펼치기 · 카톡에서 이 방 열기) / 처리(지금 재촉=문구 복사 · 내 할 일로 전환 · 차량 열기 · ERP 확인) / 분류(분류 수정 · 내 일이 아님) / 무시.
- 미루기 팝오버 = 오늘 오후 16:00 / 내일 오전 10:00 / 날짜 지정 / 상대가 답하면 / ERP 상태가 바뀌면 + 사유.
- 뺀 것(관리자 분석 화면으로 보냄): 인원 칩 · 요약 카드 · 유형/금액/확신 뱃지 상시 노출 · 아바타 · 엑셀 · 학습 설명 · 메시지 총 개수.
- 제안(미결): 「놓쳤을 가능성」만 건수 ≥1 이면 자동 펼침.

## 6. 동작 설계 (A안)

- 트레이 상주 프로그램(윈도우). 저장 = 로컬 상태 파일/SQLite — 메시지 키(방·보낸이·시각·본문 해시)별 **유형 · 방향 · 상태(할 일/기다림/미룸/완료/무시) · 다시 볼 시각 · 사유**. 그래서 다시 읽어도 새로 안 뜨고 완료·미룸이 유지된다.
- [지금 읽기] = 체크한 방을 차례로: 목록 더블클릭으로 열기 → 빈 여백 클릭 → 마지막 읽은 시각까지 PageUp(처음은 7일) → Ctrl+A·C → 파싱 → **클립보드 원복** → 다음 방. 방당 1~2초, 진행 중엔 사용자가 손 떼야 함(안내 문구).
- 미루기 시각 = 트레이가 그 시각에 올리고 뱃지. PC 꺼져 있었으면 다음 실행 때 「미룬 시점 지남」→ 놓쳤을 가능성. 조건형(상대 답·ERP 상태)은 다음 [지금 읽기] 때 판정(ERP 는 선택적으로 15분마다 가볍게 확인 가능 — 카톡은 안 건드림).
- 분류 수정 1건 = 라벨 1건 → 주 1회 재학습(로컬).
- B 단계(나중): 결과를 ERP `board_requests` 와 같은 모델로 올려 매입 탭·채권관리와 연결, PC 바꿔도 이력 유지. 개인 대화 서버 저장 → 직원 동의 필요.

## 8. 안 하기로 한 것 · 열린 것

- ✗ 채팅방 내보내기 기반 수집 ✗ 5~10분 폴링 ✗ 팀 합산 화면(1단계) ✗ GPU PC 큰 모델 분류 ✗ 개인 Claude 20석(Pro, 카카오 정책·비용·개인 계정) ✗ Jev(한국어 미검증·가입 중단).
- 열린 결정: (a) 2단계 LLM 을 붙일 때 카톡 본문을 외부 API 로 보낼지 (b) 「놓쳤을 가능성」 자동 펼침 (c) B 단계 전 직원 고지 문안.
- 카카오 정책 메모: 운영정책은 프로토콜/API 부정 호출·봇/매크로 유포를 명시 금지. 전체선택·복사는 사용자가 손으로 하는 동작과 같고 API 를 안 쓴다. 카카오 담당자가 「화면 읽고 터치」 자동화를 금지로 답한 공개 사례(devtalk 151892, 개발자 정책)는 있으므로 **자기 PC·자기 방·사용자가 누를 때만**으로 범위를 좁혀 둔다.
