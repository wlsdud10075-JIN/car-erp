## 1. 마진율 — 공식 확정 (실측)

정본 `## 2026 수출 정산_26.07.xlsx` 의 인원 탭(조하 r104~128) **CK 열** 수식을 직접 읽었다:

```
CK = CH / CC          →  마진율 = 총마진 ÷ 판매금원화(운송비 제외)
합계행(r128) = CH128 / CC128   →  Σ총마진 ÷ Σ판매금원화
```

실측값: 조하 7월분 25대 개별 1.99%~9.91%, **합계 3.59%**.

### 🚨 합계는 **평균이 아니다**

`0.0313, 0.0434, …` 를 평균 내면 안 된다. **합계끼리 나눈다**(금액 가중).
평균을 쓰면 소액 차량이 과대 반영돼 숫자가 달라진다. 엑셀 합계행이 `CH합/CC합` 인 것이 근거다.

### ERP 대응 — 이미 있는 값 둘로 계산된다

| 엑셀 | ERP | 비고 |
|---|---|---|
| `CH` 총마진 | `Settlement::total_margin` | `(판매마진 + 부가세마진) × 0.9` |
| `CC` 판매금원화(운송비 제외) | `Settlement::sales_amount_krw` | `(판매가+커미션+AL−TAX DC) × 정산환율` |

```php
// 🔑 단일 출처 — 조건을 옮겨 적지 말 것 (§8 #44)
public function getMarginRateAttribute(): ?float   // Settlement
{
    $base = (int) $this->sales_amount_krw;
    return $base === 0 ? null : $this->total_margin / $base;   // 0 이면 null
}
```

- **합계용은 별도 헬퍼**로 두고 같은 식을 쓰게 한다 — 예: `Settlement::marginRateOf(Collection $rows)`
  = `Σtotal_margin / Σsales_amount_krw`, 분모 0 이면 null.
- ⚠️ **`null` 을 0% 로 그리지 말 것** — 판매금원화가 0 인 차(판매 전·내수 등)는 「−」로 표시한다.
  0% 로 그리면 합계 평균을 눈으로 계산할 때 오해한다.
- ⚠️ **내수 차량**은 `is_domestic` 이라 마진 공식 자체가 다르다(`domestic_margin`).
  마진율을 그대로 쓸지, 내수는 「−」로 뺄지 **결정 필요**(아래 §4).

### 표시 위치

| 어디 | 무엇 |
|---|---|
| 월배치 드릴다운 **차량 줄** | 그 차의 마진율 |
| 월배치 드릴다운 **사람 소계 줄** | 그 사람의 총 마진율 (Σ/Σ) |
| 월배치 **카드 상단** | 배치 전체 마진율 (`profitStats()` 에 항 추가) |
| (선택) 정산관리 목록·엑셀 내보내기 | 같은 accessor 재사용 |

## 2. 예치금 · 기본급 — 담당자에 붙는 두 금액

### 저장

`salesmen` 에 컬럼 2개 추가:

| 컬럼 | 대상 | 뜻 |
|---|---|---|
| `deposit_krw` | **프리랜서** | 보유 예치금(보증금) 잔액 |
| `base_salary_krw` | **사내직원** | 월 기본급 |

- 타입은 `decimal(15,2)` 아니라 **`unsignedBigInteger` 또는 `integer`** 로 충분하다(원 단위, 소수 없음).
- 기본값 `null` — **0 과 미입력을 구분**한다(미입력이면 화면에서 「−」).

### 입력 화면 — 기존 tier 체크박스 자리를 그대로 따른다

`resources/views/livewire/erp/salesmen/index.blade.php` 편집 패널에 이미 같은 형태가 있다:

```php
$linkedUserType = $editingSalesman?->user?->type;      // 'freelance' | 'employee'
@if($linkedUserType === 'employee' && auth()->user()?->canApprove())  ... per_unit_tier ...
```

⇒ **같은 분기**로:
- `freelance` → **예치금** 입력칸
- `employee` → **기본급** 입력칸
- 권한 = **`canApprove()`**(관리 이상). 돈 직결이라 tier 와 같은 선.

🔑 **타입 자체는 `/admin/users`(사용자관리)에서만 바꾼다** — `Salesman.type` 은 `User.type` 의 미러다
(2026-05-21 결정, 화면에 그렇게 적혀 있다). jin 말의 *「사용자관리에서 … 에 따라서 기입」* 이 이 구조다.

⚠️ **타입이 안 붙은 담당자**가 있다 — `user_id` 가 없거나 `user.type` 이 비면 화면이 「계정 없음/미설정」을 띄운다.
그 경우 **두 칸 다 숨긴다**(잘못된 칸에 금액이 들어가는 것보다 낫다).

### 🧾 감사로그 — 직접 남겨야 한다

`Salesman` 에는 감사 훅이 **없다**. `payout_excluded` 를 넣을 때(2026-09-16) 저장부에서 직접 기록했다(§8 #103).
예치금·기본급도 **돈이 오가는 스위치**이므로 같게 한다.
⚠️ `AuditLog::isRealChange()` 를 쓸 것 — `wasChanged()` 만 쓰면 숫자 표기 차이로 소음이 쌓인다(§8 #108).
🗣️ 새 action 을 만들면 **같은 커밋에 `config/column_labels.php` 한글 라벨**(§8 #41).

## 3. 월배치 표시 — 「기본급 + 정산금 = 월급」

사내직원 소계 줄을 이렇게:

```
조하   26건 · 정산 1,800,000  +  기본급 2,740,000  =  월급 4,540,000     마진율 3.6%
```

프리랜서는:

```
와심   43건 · 지급 11,842,007                          예치금 보유 10,000,000     마진율 4.1%
```

- **예치금은 지급액에 더하지 않는다** — jin *「예치금은 그냥 보유하면되고」*. **보유 잔액 표시**일 뿐이다.
- 반환이 일어나는 달은 **배치 수동 조정**으로 넣는다(9/10 에 김연아 5,000,000 · 가태웅 10,000,000 을 그렇게 했다).
  🅿️ 반환 이력을 남기는 「예치금 원장」은 **2차 과제**로 미룬다([[project_freelancer_deposit]]).

## 4. ✅ 결정 완료 (jin 2026-09-18)

### ① 기본급은 **표시만** — 배치 총액에 안 넣는다

> jin: *「표시만해서 총액을 얼마 받는다만 해주면 될거같은데? 기본급 = 얼마 / 정산 = 얼마 / 실지급액 = 얼마」*

사내직원 소계 줄을 **3줄**로:

```
조하      마진율 3.6%      26건
  기본급        2,740,000
  정산          1,800,000
  ───────────────────────
  월수령액      4,540,000
```

- `SettlementPayoutBatch::total_payout` 은 **정산만** 유지한다 → **회사이익 공식 무영향**
  (`총마진 − payout − 발송비`. 급여를 넣으면 이 지표의 뜻이 바뀐다 — §8 #72 의 그 형태).
- 대표 알림톡 총액도 지금 성격 그대로.
- 배치 카드에 **「+ 기본급 합계 = 이달 송금 예상」** 한 줄을 따로 둔다(통장 대조용).

🚨 **용어 충돌 — 「실지급액」을 재사용하지 말 것.**
ERP 에서 **실지급액 = `Settlement::actual_payout`**(정산액 − 서류비 − 발송비 − 기타공제)으로
**이미 정산관리·월배치·엑셀 내보내기 3곳에서 쓰고 있다**(`lang/ko/settlement.php:149,166`).
같은 단어가 화면마다 다른 숫자를 가리키면 «정산관리는 1,800,000 인데 월배치는 4,540,000» 이 된다.
⇒ 합계 줄의 이름은 **「월수령액」**으로 한다 (jin 2026-09-18 확정).

프리랜서는 기본급이 없으므로 2줄 + 보유 예치금:

```
와심      마진율 4.1%      43건
  정산         11,842,007
  (예치금 보유 10,000,000)
```

### ② 내수 차량은 마진율에서 **통째로 뺀다**

> jin: *「내수는 마진률이 없지. 그냥 넣지말아버려. 그것도 마진률의 평균에도 들어가지않게.」*

- 차량 줄: 마진율 칸에 **「−」**
- 사람·배치 합계: **분자(총마진)·분모(판매금원화) 양쪽에서 제외**
  🚨 분모에서만 빼면 마진율이 부풀고, 분자에서만 빼면 깎인다. **둘 다** 빼야 한다.
- 판정 = `Settlement::is_domestic` (정산행에 박제된 값. 차량의 현재 상태가 아니라 **그때의 판정**이라 소급 변동이 없다)
- ⚠️ 건수 표시는 그대로 센다(정산 대상이긴 하다). **마진율 계산 모수만** 다르다.

### ③ 열람 권한 — **[관리] 이상 유지**

지금 월배치 화면 권한 그대로. 별도 좁히지 않는다.

### ④ 예치금 — **보유액 한 칸**. 이력은 다음 과제

> jin: *「이력은 다음과제로 하자.」*

반환이 일어나는 달은 **배치 수동 조정**으로 처리한다(9/10 에 김연아 5,000,000 · 가태웅 10,000,000 을 그렇게 했다).
🅿️ 예치금 원장(입출금 이력)은 [[project_freelancer_deposit]] 로 미룬다.

### ⑤ (참고) 마진율 기준 환율 — 소급 보정하지 않는다

`sales_amount_krw` 는 **정산환율**(실입금환율)을 쓴다. 엑셀 CC 도 같다 ✓.
다만 소급 적재분(7·8월)은 ERP 가 판매환율로 폴백해 **과거 달 마진율이 엑셀과 다를 수 있다**
(9월 귀속분은 171/189 가 실입금환율 — 문제 없음). 🚫 잔금 환율을 고쳐 맞추지 말 것(§8 #80·#83).

## 5. 작업 순서 (착수 시)

```
1. 마이그레이션  salesmen +deposit_krw +base_salary_krw          → verify: 3사 스키마
2. Settlement::margin_rate + 합계 헬퍼 (단일 출처)                → verify: 조하 7월 25대로 엑셀 CK 대조
3. 영업담당자 편집 패널 입력칸 2종 (타입 분기 · canApprove · 감사) → verify: 타입별 노출·권한·감사로그
4. 월배치 화면 — 차량줄/사람줄/카드 마진율 + 「기본급+정산=월급」   → verify: 배치 #2 로 눈 대조
5. lang ko/en 동시                                              → verify: LocaleKeyParityTest
```

### 🔒 가드로 박을 것

- **합계 마진율이 평균이 아니다** — 금액이 크게 다른 2대로 평균≠가중 을 드러내는 테스트
- **분모 0 → null**, 화면은 「−」
- **마진율 계산이 한 곳뿐** — 정적 검사(`total_margin` 을 `sales_amount_krw` 로 나누는 식이 2곳 이상이면 실패)
- **타입별 칸 노출** — freelance 에 기본급칸이 안 뜨는지 / 타입 미설정이면 둘 다 안 뜨는지
- **월배치 화면은 `wire:poll` 이 아니다**(확인함) — 그래도 마진율을 행마다 accessor 로 돌리면
  560건 × 2 accessor 다. **eager load 와 합계 1회 계산**으로 짤 것(§8 #96-C).

  🚫 단, **캐시 컬럼을 새로 만들면 재계산 대상이 하나 더 는다**(§8 #101) — 먼저 실측하고 결정한다.
