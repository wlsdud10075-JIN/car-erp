## 💰 돈 ④ 2차 정산 · 이월 · 잠금 (코드 대조 2026-11-20) — 독립 대조 1회 반영

> 🚫 **이월·잠금 판정을 옮겨 적지 않는다.** 이월은 `Salesman::unconsumed_carryover`, 잠금은 `Vehicle::hasClosedSecondarySettlement()`(기존 값 수정) · `Vehicle::ledgerLockedForNewPayments()`(새 입금) 두 술어만 쓴다.
> 1차 공식은 돈 ①, 환차·`fx_excluded`·`exchange_difference_krw` 의 뜻은 돈 ② 를 본다.

### 1. 1차 상태 (`settlement_status`: pending → calculating → confirmed → paid)
| 전환 | 누가 | 막는 것(`Settlement::saving`) |
|---|---|---|
| → confirmed (행 버튼·월 일괄 확정) | `canConfirmFinance` = 재무·관리·업무관리자·최고/시스템관리자 | 비율 정산인데 비율 0 · karaba 인데 매입세액 미입력(null) |
| → paid | 최고/시스템관리자 직접, 또는 월정산 최종 승인(`execute`)·개별 지급 승인(대표만 실행) | 그 밖의 로그인 사용자가 직접 paid 로 바꾸면 예외. 미수로 지급보류된 정산은 개별 승인도 막힌다(게이트 예외 건은 통과) |
| 삭제 | pending · calculating 만 | confirmed · paid · 2차 마감 행은 예외(로그인 없는 콘솔·시드는 통과) |

**paid 로 넘어가는 저장 한 번에 자동으로 일어나는 일**
- `secondary_status = 'pending'`(이미 값이 있으면 그대로) · `secondary_ready_at = null`(지급 전에 넣은 비용은 「2차 가능」 근거가 아니다)
- 빈 비율·빈 건당액을 그때 값으로 채워 고정한다(`effective_ratio` · `effective_per_unit_amount`)
- `fx_excluded` 가 비어 있으면 박제(돈 ②)
- `confirmed_snapshot`(비어 있을 때만) = 판매환율·면장금액·운임비·매입가·비용합계 + 판매금원화·정산판매금원화·판매마진·부가세마진·총마진·정산액·**실지급액**·발송비 + 확정된 판매 입금 줄/매입 지급 줄 목록. 건당 정산은 `per_unit_auto`(자동 등급이었나)도 같이 박는다.
- `paid_at` 은 훅이 아니라 호출부가 넣는다.

⚠️ **알려진 구멍(2026-11-20 대조에서 확인, 미수정)** — 정산 편집 드로어(`settlements/index` `save()`)는 지급·마감된 행에도 열리고 상태·비율·건당·기타공제·담당자를 그대로 저장한다. `Settlement::saving` 은 「paid 가 되는 순간」만 보고 **역행 가드가 없다**(paid → 확정/대기로 내리기, 2차 대기 행을 대기로 내린 뒤 삭제 가능). 지급보류(미수) 검사는 월정산·개별 승인에만 있고 최고관리자의 드로어 직접 paid 전환에는 없다.

### 2. 2차 마감 (`secondary_status`: pending → closed)
- **권한** = 최고/시스템관리자 · 재무 · 관리(업무관리자는 role 칸이 재무·관리일 때만 — `isAdmin()` 에 업무관리자가 없다). **막는 사유는 둘뿐** = 2차 대기가 아님 / 외화 차인데 판매환율이 없음. 🔎 **미수가 남아 있어도 마감된다**(게이트 예외 여부와 무관).
- 2차 대기는 둘로 갈린다 — 지급 뒤 비용 10칸 중 하나가 실제로 바뀌면 「2차 가능」(`secondary_ready_at`), 아니면 「비용 대기」.
  **일괄 마감**은 귀속월을 고른 상태에서 화면 필터에 걸린 「2차 가능」만 닫는다. 「비용 대기」는 단건 버튼으로만 닫는다. (귀속월 요구는 버튼·모달 쪽 가드다.)
- 마감 때 저장되는 값(`closeOne`):
```
exchange_difference_krw = computeExchangeDifference()             ← 감사·참고용(돈 ②)
secondary_fx_krw / secondary_cost_krw = 마감 직전 분해값 박제     ← 마감 뒤 다시 계산하지 않는다
(건당·자동 등급이고 건당액 칸이 채워진 행이면) per_unit_amount = 지금 총마진으로 다시 매긴 등급
carryover_out_krw = 마감 시점 실지급액 − confirmed_snapshot.actual_payout    (0 이면 안 쓴다)
```
- 🚨 **지급 스냅샷이 null 인 행은 이월을 만들지 않는다**(적재분 등 — 기준이 없으면 실지급액 전액이 이월로 둔갑한다).
- ⚠️ `closeOne` 은 트랜잭션이 아니다(마감 저장 → 건당 재평가 → 이월 저장, update 3번). 중간에 예외가 나면 「마감됐는데 이월이 없는」 행이 남고 화면에서 다시 닫을 수 없다.
- 마감은 화면에서 되돌릴 수 없다. 되돌리기는 콘솔 `settlements:reopen-secondary`(마감 때 값 3칸을 지우고 pending 으로) 뿐이다. 분해 박제 2칸과 재평가된 건당액은 남는다. ⚠️ 이 명령은 `carryover_in_krw` 만 보고 **청산 기록(`CarryoverClearance`)을 안 본다** — 이미 월정산에 실린 이월의 마감을 풀면 미청산 잔액이 반대 부호로 남는다.

### 3. 이월 — 누가 언제 가져가나
```
미청산 이월(사람별) = Σ 마감 정산의 carryover_out − Σ carryover_in(옛 방식 흡수분) − Σ 청산 기록(CarryoverClearance)
```
- **지금 도는 경로는 하나** — 월정산·퇴사 정산을 **제출할 때** `SettlementPayoutBatch::carryoverLinesFor` 가 사람별 조정 한 줄(`kind=carryover`)을 만들고 청산 기록을 남긴다. 반려되면 청산 기록을 지워 다음 제출에 다시 나온다(상세 돈 ⑤). 결재 대기 중인 배치의 이월은 이미 청산된 것으로 잡힌다. + 이월은 전액, − 이월은 그 사람의 이번 배치 지급액까지만. 지급 제외 담당자·즉시 정산 퇴사자(월정산에서)는 건너뛰고 내수 배치는 안 가져간다.
- 🚫 `Settlement::creating` 의 흡수 훅은 **꺼져 있다**(`$absorbCarryoverOnCreate = false`). 운영 코드에서 켜지 않는다 — 둘 다 돌면 두 번 지급이다. 옛 행의 `carryover_in_krw` 는 실지급액에 그대로 더해진다(역사).
- 이월에 담기는 것 = 지급 뒤 실지급액을 바꾼 **전부**(비용·판매가·환율·기타공제·서류비, 환차 포함 정산의 입금 환차 — 돈 ②). 그리고:
  - **발송비**: 비율 정산은 직원 몫(50%)이 실지급에서 빠지므로 지급 뒤 발송비가 생기면 그만큼 − 이월.
  - **사내직원(건당)**: 지급 때 건당액이 고정되지만, 자동 등급으로 정해진 건이면 마감 때 `retieredPerUnitAtClose()` 로 다시 매겨 차액이 이월된다(판정 마진에 발송비 직원 몫 포함). 재무가 직접 넣은 건당액·스냅샷 없는 행은 다시 매기지 않는다. 스냅샷에 `per_unit_auto` 키가 없는 옛 행은 2026-08-06 뒤 지급분만 다시 매긴다.

### 4. 잠금 — 무엇이 언제 잠기나
| 대상 | 잠기는 때 | 열리는 길 |
|---|---|---|
| 차량 회계 27칸(`Vehicle::LEDGER_LOCK_FIELDS` — 금액 25 + 바이어·담당자) | 2차 **마감 뒤**(모델 `guardLedgerLockOnSaving`). 빈 값 → 첫 입력은 통과 | 회계 재조정 토큰 |
| 차량 패널의 금액 25칸(화면 가드 `guardFinancialDriftAfterPaid`) | **지급(paid) 뒤**부터. 2차 대기 동안은 재무 이상(`canCorrectSecondaryCosts`)만 통과. **빈 값 → 첫 입력도 막는다**(모델 가드와 다르다 — 마감 차의 빈 칸을 채울 때도 토큰이 필요) | 2차 대기(재무 이상) · 토큰 |
| 확정된 판매 입금 줄·매입 지급 줄의 금액·날짜·환율 수정, 삭제 | 마감 뒤(모델 훅 — 재무처리·채권관리 화면 경로). 확정 해제·이체 연결은 언제나 불가. ⚠️ **차량 패널 저장은 예외**(아래 구멍) | 재무처리 화면은 마감 차를 아예 막는다 |
| **새** 판매 입금 줄 · 그 재무 확정 · 채권관리 「입금」 | 마감 **그리고 미수 ≤ 0** | 미수가 남아 있으면 열려 있다 · 토큰이 살아 있는 동안 |
| 발송(EMS·DHL) **금액** | 마감 뒤. 번호·날짜·비고와 0원 줄은 계속 고친다 | 토큰 |
| 판매탭 「송금 수수료」 칸 | 마감 뒤 | 없음(토큰이 있어도 건너뛴다) |
| 새 매입 지급 줄 | 안 잠긴다(정산 뒤 매입 지급이 정상 흐름) | — |
| 매입탭 계약금·매도비 지급 칸 | 안 잠긴다(마감 검사 없음) | — |

- 마감 전에는 확정 줄이 있어도 차량 회계 칸·지급 줄을 고칠 수 있다. 그 변동이 2차 마감 때 이월로 정리된다.
- 차량 삭제: 정산이 confirmed·paid·마감이면 누구도 못 지운다(콘솔도). 확정 줄이 있는 차는 최고/시스템관리자·업무관리자만 지운다. pending 정산은 차량과 같이 지워진다.
- 차량 회계 칸·새 입금·발송·정산 삭제 가드는 로그인한 저장에만 건다. 확정 줄 수정·삭제 훅과 차량 삭제의 정산 가드는 콘솔에서도 건다(적재는 `withoutEvents` 로 피한다).

⚠️ **알려진 구멍(2026-11-20 대조에서 확인, 미수정)**
- **차량 패널은 판매 입금 줄·매입 지급 줄을 bulk 쿼리로 고치고 지운다**(잠금 훅을 일부러 피하는 설계) — 그 구간에 마감 판정이 없다. 그래서 2차 마감 차의 **확정 매입 지급 줄**을 매입탭에서 고치거나 지울 수 있고(이체 연결 줄만 제외), 판매 입금 줄은 채권관리 거울이 없는 줄(엑셀 적재분)이 같은 상태다(화면에서 만든 줄은 거울 잠금에 걸려 읽기 전용).
- 줄 단위 잠금 해제(`unlockForFinalPayment`·`unlockForPurchasePayment`·`unlockForCostBulk`)는 정의만 있고 호출처가 없다 — 마감 뒤 확정 줄 정정의 정식 경로가 없다.

**회계 재조정 토큰** — 정산 화면 마감 행의 [🔓 회계 재조정]에서만 발급된다.
- 발급 조건 = `canUnlockLedger`(관리자급 전체 · 관리는 본인 팀 차) + 사유 10자 + 그 차가 마감 상태. 감사로그 `ledger_field_unlocked`, 유효 5분.
- 소비(1회) = 잠긴 칸의 **기존 값이 실제로 바뀌는** 차량 저장, 또는 마감 차의 발송 금액 변경. 화면 가드·새 입금 판정은 토큰을 보기만 한다. 토큰은 차량 단위다(사용자 구분 없음).
- ⚠️ 빈 칸 **첫 입력**은 화면 가드 때문에 토큰이 필요한데 모델 가드가 소비하지 않는다 → 토큰이 5분간 남아 그동안 그 차의 다른 잠긴 칸 1회 수정·새 입금·발송 금액이 열린다.
- 🚨 **재조정은 기록만이다.** 마감 뒤에 `carryover_out_krw` 를 다시 쓰는 코드가 없다 — 차량 값을 고치면 실시간 accessor(`actual_payout`·`company_net`)는 움직이지만 이월·지급은 따라가지 않는다(3차 정산 없음). 마감 뒤 들어온 입금도 담당자 정산에 반영되지 않는다.
  재조정 뒤 **움직이는 화면** = 정산관리 목록·담당자 카드 합계·관리자 대시보드 회사이익(실시간 accessor). **안 움직이는 화면** = 2차 차액 분해·미청산 이월·승인된 월정산 카드·대시보드 지급액 차트(박제). 실제 지급액은 `confirmed_snapshot` 과 배치 박제에만 남는다.

### 5. 명세서 일괄 기입 (`BulkVehicleCostService`)
- 넣을 수 있는 칸 = 비용 10칸(`Vehicle::BULK_COST_FIELDS`)뿐. 권한 = 재무 이상(`canCorrectSecondaryCosts`), 팀 모드는 `canUnlockLedger` 또는 재무.
- **2차 마감 차는 건너뛴다**(`settlement_closed`) — 토큰을 자동으로 쓰지 않는다. 같은 값이면 안 건드린다.
- 모델 update 라 `Vehicle::updated` 훅을 탄다 → 감사로그 + 그 차의 2차 대기 정산이 「2차 가능」으로 바뀐다.
- **보험료(`cost_insurance`)만 기존 금액에 더한다.** 탁송비·면허비·캐리비는 덮어쓴다. 더하기는 같은 파일을 두 번 올리면 두 배라, 올린 파일 지문(칸 + 차량:금액 목록)을 회사별 설정에 최근 50개 보관하고 같은 지문이면 막는다(알고 올릴 때만 체크박스로 통과).
- 발송 일괄 기입은 마감 차에 번호·날짜만 넣고, 금액은 마감 안 된 차들에게만 n/1 로 나눈다.

### 6. 🚫 하지 말 것
- `carryover_out_krw` 를 마감 밖에서 쓰거나 고치지 않는다. 미청산 잔액을 손으로 다시 세지 않는다.
- 새 배치 종류를 만들면 이월을 가져갈지부터 정한다(안 가져가는데 청산 기록만 만들면 돈이 사라진다).
- 마감 판정을 `paid`·확정 줄 유무로 대신하지 않는다. 반대로 화면 가드의 `paid` 기준을 `closed` 로 「통일」하지 않는다(2차 대기 동안 영업이 금액을 고치게 된다).
- 화면 가드·새 입금 판정에서 토큰을 `pull` 하지 않는다(같은 저장의 모델 가드가 막힌다).
- **새 코드에서** 지급 줄·발송 줄을 bulk 쿼리로 고치거나 지우지 않는다 — 잠금 훅·캐시 갱신·감사가 통째로 빠진다. (차량 패널의 기존 bulk 저장은 위 「알려진 구멍」 — 모델 삭제로 바꾸면 잠금 가드가 살아나 마감 차 저장이 막히므로 jin 결정 뒤에 고친다.)
- 보험료를 덮어쓰기로, 탁송비·면허비를 더하기로 바꾸지 않는다.
- `confirmed_snapshot` 을 훅과 백필 명령 밖에서 만들지 않는다(`buildConfirmedSnapshot()` 한 곳).
