# 문서 용량 줄이기 — 진행 상태 (jin 2026-11-20 착수, 주말 작업과 함께 적용 → 그 뒤 스킬화)

> 세션이 바뀌어도 여기부터 읽고 이어간다. 정한 것·남은 것이 전부 이 파일에 있다.

## 왜
세션 시작 때 CLAUDE.md(52KB)·SKILLS.md(181KB)·메모리 색인(27KB)이 전부 실려 컨텍스트의 25~31%를 쓴다.
줄이는 과정에서 **원본이 낡은 곳**도 드러났다(환차 11-17 변경 미반영 · 회사이익의 유형별 차이 · 사내직원 건당 6단계 · 미러 방식 4종).

## jin 이 정한 구조 (3단)
1. **매 세션 읽는 핵심** — 돈 · 역할 · 락 + (내가 제안해 넣기로 한) 배포·금지 명령 · 진행상태 10단계 · 「떠난 차」 판정 · 누르면 안 되는 것 · 세션 간 통신 규약.
   줄이지 않고 **코드와 대조해 다시 쓴다**(원본을 줄이는 게 아니다). jin «돈 관련은 절대 틀어지고 까먹으면 안 된다».
2. **색인 한 줄(쓸 때만 불러옴)** — 공용 부품·서류 양식·알림톡 등록·가이드 촬영 등. Claude Code 스킬로 옮긴다(설명 한 줄만 실리고 본문은 부를 때 읽힌다).
3. **보관** — 경위·날짜·그때의 실측. `docs/archive/` 로.

핵심 목록 전문(항목별) = 메모리 `project_md_context_trim` 「매 세션 읽을 핵심 목록」.

2. **역할** 편: 권한 4단·미들웨어 표·「관리 이상」·역할의 실제 일·승인 권한·담당 범위·**알림톡 수신자 규칙**(jin «나중에 찾으려면 그게 더 클 것 같아»).
3. **락** 편: 매입 등록 락·수출 진입 게이트·B/L 100%·기준값(기능설정)·우회 승인·매입 락 해제 승인·일반재고 2억·정산 잠금·회계 재조정·확정 입금 잠금.
4. 편마다 jin 에게 보여 확인받는다(시험은 「적혀 있나」만 잡고 「맞나」는 못 잡는다 — 돈은 jin 이 직접 읽는다).
5. 적용: 원본을 `docs/archive/md-2026-11-XX/` 에 통째 보존 → 줄인 판으로 교체 → `docs/operations/new-pc-setup.md` 새로 만들기(줄인 판이 가리킨다).
