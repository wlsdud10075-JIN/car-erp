## 💰 돈 ③ 받을 돈 · 줄 돈 (코드 대조 2026-11-20 — `app/Models/Vehicle.php`, 독립 대조 1회 반영)

> 🚫 **미수·미지급을 SQL 로 다시 세지 않는다.** 아래 accessor·스코프·캐시 컬럼만 쓴다. 규칙을 다 알고 손으로 재현해도 대수가 어긋난 실례가 있다(16대 → 17대·21대).

### 1. 한 글자 차이인데 뜻이 다른 세 합계 — 서로 대신 쓰지 않는다
| 이름 | 식 | 뜻 | 단일 출처 |
|---|---|---|---|
| **총판매가** | 판매가 + 운임비 + 기타판매비용 + 커미션 + AL − TAX D/C | 바이어에게 **받을 돈**(미수의 분모) | `Vehicle::sale_total_amount` |
| **정산 기준액** | 판매가 + 커미션 + AL − TAX D/C | 담당자 **마진** 계산(돈 ①) | `Settlement::sales_amount_krw`(× `settlementRate()` — 돈 ②) |
| **면장 기준액** | 총판매가 − 기타판매비용 | 세관에 신고하는 **물건 값**(운임비는 CIF 라 남는다) | `Vehicle::declaration_base_amount` |

- 정산 기준액 식은 **수출 정산** 기준이다. 내수 정산(`is_domestic`)은 총판매가를 환율 없이 그대로 쓴다.
- 운임비·기타판매비용은 회사가 대신 치르고 되받는 돈이라 **마진이 아니다**. B/L 재발급비 같은 뒤늦은 비용은 `sale_other_costs` 에 넣는다 → 받을 돈이 늘고, 정산 기준액(외화)·면장은 안 움직인다.
  ⚠️ 다만 실효 입금환율의 분모가 총판매가라, 환차 포함 방식에서 이미 환차가 실현된 외화 차는 정산 원화가 조금 달라질 수 있다(환차 제외·원화 차는 무관).
- 면장금액(`export_declaration_amount`) 저장 규칙(판매가 > 0 일 때만 돈다): ①비었으면 면장 기준액으로 채운다 ②자동으로 채워졌던 값(이전 면장 = 이전 기준액)이면 판매 금액이 바뀔 때 따라간다 ③사람이 다른 값을 넣었으면 보존한다. 정산에 안 쓰인다.

### 2. 판매 미수 (`Vehicle::sale_unpaid_amount` — 그 차 통화 그대로)
```
받은 돈 = 확정된(confirmed_at 있음) 판매 입금 줄 합 — 종류(계약금·중도금·선수금·수수료·잔금) 무관
        + 채권관리 회수 기록 합 — 단, 미러 방식 4종은 제외
        + 적립금 사용(savings_used)
미수    = 총판매가 − 받은 돈          (0 초과 1 미만이면 0 으로 — 외화 소수점 잔차. 음수 = 과입금은 그대로 둔다)
미수율  = 미수 ÷ 총판매가 (0~1, 총판매가 ≤ 0 이면 null, 과입금은 0)      ← Vehicle::unpaid_ratio
```
- 🚨 **확정 안 된 입금 줄은 안 센다.** 「입력했는데 미수가 그대로」의 1순위. 채권관리에서 「입금」으로 넣어 생긴 거울 입금 줄도 확정 전에는 미수를 안 줄인다.
- 🚨 **미러 방식 4종**(`Vehicle::MIRRORED_RECEIVABLE_METHODS` = `deposit`·`savings`·`misc_loss`·`company_income`)은 다른 곳에 이미 잡힌 돈의 **거울 줄**이다(입금 줄·적립금 사용·과입금 정리). 회수 기록에서 이걸 또 빼면 이중 차감이다.
  채권관리 「적립금」 회수 줄은 줄 자체는 안 세지만 `savings_used` 를 움직여 미수가 바뀐다.
- **현금·상계·기타(`other`)·손실(`write_off`) 회수 줄은 받은 돈으로 센다**(미러가 아니다) — 미수를 줄인다. 「과거데이터 임포트」 표식의 기타 줄도 같다(실제 수령이 아니라 정리분).
- 🧾 **클레임 사용**(판매탭 「클레임 사용」 칸, `App\Services\ClaimUsage`)은 채권관리에 **상계 줄**(`source='claim'`)을 자동으로 만든다. 미수 공식은 그대로다 — 상계는 회수 기록이라 받은 돈으로 세어진다. 그래서 미수만 줄고 정산액·마진·회사이익 숫자는 안 바뀐다(회사 부담, 손실로 따로 표시하지 않는다). 인정된(`accepted`) 클레임만 · 같은 통화만 · 오래된 클레임부터 · 누적금과 그 차 미수를 넘겨 쓸 수 없다 · 바이어 없는 차는 못 쓴다 · 마감 차도 미수가 있으면 가능. 이 줄은 채권관리에서 고치거나 지울 수 없다(판매탭에서만).
- **원화 환산 미수** = 캐시 컬럼 `sale_unpaid_amount_krw_cache`(차량 저장·입금/회수 줄 저장 때 갱신, 판매환율 기준). 환율이 없는 외화 차는 `null` — 「환율 미입력」으로 따로 다룬다. 대시보드·알림톡·채권관리 전체 보기 합계는 이 컬럼을 더한다. 채권관리에서 통화를 고르면 그 통화의 `sale_unpaid_amount` 를 더한다.
- **집계 미수율**(여러 대를 묶어 볼 때) = Σ원화 미수 ÷ Σ(총판매가 × 판매환율). 분모에 운임비 등 부대비용이 **들어가야** 분자와 맞는다. 환율 없는 외화 차는 분자·분모 둘 다 뺀다. 업무 대시보드는 `Vehicle::aggregateUnpaidRatioPct`, 채권관리는 같은 식을 화면에서 직접 계산한다.
- **실입금 원화**(`sale_received_krw_accumulated` — 환차 계산의 기준) = 확정 입금 줄 × 그 줄의 환율(없으면 판매환율) + 회수 기록(미러 제외) × 판매환율 + 적립금 사용 × 판매환율. 원화 차는 저장 때 환율이 1 로 고정된다.

### 3. 매입 미지급 (`Vehicle::purchase_unpaid_amount`)
```
총매입액 = 매입가 + 매도비                                   ← purchase_total_amount
지급액   = 매입 지급 줄 중 「확정됨」 그리고 「지급일 ≤ 오늘」인 것의 합 — 종류(계약금·잔금·매도비) 무관
미지급   = 총매입액 − 지급액
```
- 🚨 **지급일이 미래인 줄·확정 안 된 줄은 안 센다.** SQL 짝 = `Vehicle::purchaseUnpaidRawExpr()`.
- 매입 탭 화면에는 계약금·매도비 칸이 그대로 있다. 저장은 **종류(type)가 붙은 지급 줄**(`purchase_balance_payments`)로 된다 — 차량 컬럼에 따로 쌓이는 것이 아니다.
- **재고**(`scopeInStock`) = 매입가 > 0 · 미지급 ≤ 0 · 아직 안 나감(출고일 없음 그리고 선적일 없거나 미래) · 거래완료 아님 · 매입취소 아님. 입고일 = 마지막 확정 지급일.
- **지급대기** = 매입가 > 0 · 미지급 > 0 · 출고일 없음 · 거래완료 아님 · 매입취소 아님. ⚠️ 지급대기는 선적일을 안 본다 — 과거 선적일이 있어도 미지급이 남으면 지급대기에 남는다.

### 4. 「떠난 차」 판정 — 선적 전 미수와 선적 후 미수를 가른다
```
떠났다(departed) = 출고일 있음 | B/L 파일 있음 | B/L 발행일 ≤ 오늘 | 선적일 ≤ 오늘
```
- 단일 출처 `Vehicle::scopeDeparted()` / `scopeNotDeparted()` / `isDeparted()`(모델 없는 행은 `departedFrom`). 🚫 조건을 옮겨 적지 않는다(채권 분류가 화면·대시보드·알림톡·포털에 흩어져 있다).
- 날짜는 **과거만**(미래 선적일은 아직 안 떠난 것), 오늘 포함. 🚫 `bl_number`(자유 입력칸)·반입지(`bl_loading_location` — 항구 주차장에 세우려고 먼저 찍는다)로 판정하지 않는다. 반입지는 진행상태 단계에만 쓴다.
- **결제대기(grace)**: 안 떠난 차의 미수는 판매일 + 유예일(`Setting::graceDays()`, 기본 10일) 전까지 채권·선적 전 미수 알림에서 뺀다. 떠난 차는 유예 없이 바로 채권.
- ⚠️ **매입 등록 락의 「선적 전」은 이 판정이 아니다** — 거래완료 차를 먼저 빼고, 남은 차 중 **출고일 있는 차**만 뺀다(`Buyer::computeReceivableGauge`, 락 절 참조). 일부러 다른 기준이다. 미수는 원화 캐시를 쓰므로 환율 없는 외화 차는 0 으로 들어간다.

### 5. 채권 위험 등급 (`receivable_risk` 캐시 — `getReceivableRiskComputedAttribute`, 위에서부터 첫 매칭)
| 등급 | 조건 |
|---|---|
| none | 총판매가 ≤ 0 (판매 전) |
| safe | 미수 ≤ 0 (과입금 포함) |
| critical | B/L 파일 있음 · 또는 배가 도착(선적일·ETA 둘 다 있고 ETA 가 오늘이거나 지남) — 받을 수단이 사라졌다 |
| danger | 떠났는데 선적 게이트 미달 · 또는 안 떠났는데 판매 후 N일(`Setting::receivableStaleDays`, 기본 90) |
| grace | 안 떠났고 유예일 이내 |
| caution | 나머지 |
- ⚠️ danger 가 grace 보다 위다 — 설정에서 N일을 유예일 이하로 잡으면 유예 중인 차가 danger 가 된다.
- 캐시 컬럼이라 **규칙을 바꾸면 배포만으로 안 바뀐다** — `vehicles:rebuild-caches`(야간 05:00 자동, 급하면 수동). 차량 저장·입금/회수 줄 저장 때도 그 차는 갱신된다. 시간 경과에 따른 등급 변화는 야간 재계산으로 반영된다.
- 게이트 임계는 바이어별 재정의를 따른다(`LockThresholdResolver`). 알림톡은 등급 컬럼을 안 쓴다 — 선적 전/후·결제대기 분류와 도착(ETA) 판정을 쓴다.

### 6. 정산과의 연결
- 정산 행을 만드는 **계기** = 판매 입금 줄 저장 · 회수 줄 저장(방법 무관 — 현금·상계·기타·클레임 사용 포함) · 거래완료 진입 · 인코텀즈/운임비 변경 · 내수 차의 기준액 칸 변경. **전부 로그인한 사용자의 저장에서만 울린다**(콘솔·시드·적재·raw update·일괄 경로는 안 울린다).
- 계기가 울려도 안 만드는 경우 = 매입취소 · 판매가 없음 · 미수 > 0 · 담당자 없음 · 이미 있음 · 운임 미확정 · 내수 차액 0. 「조건은 다 맞는데 정산이 없다」면 계기가 울렸는지부터 본다.
- 채권관리에서 「기타」·현금·상계로 털어도 판매 입금 줄은 안 생긴다(거울 줄이 생기는 것은 「입금」 한 종류뿐).
- 2차 마감됐고 **미수가 없는** 차에는 「입금」 줄을 새로 못 넣는다(회계 재조정 토큰이 살아 있는 동안만 열린다). 마감됐어도 미수가 남아 있으면 넣을 수 있다. 현금·상계·기타는 언제나 들어간다(돈 ④ 잠금 표).
