## 💰 돈 ③ 받을 돈 · 줄 돈 (코드 대조 2026-11-20 — `app/Models/Vehicle.php`)

> 🚫 **미수·미지급을 SQL 로 다시 세지 않는다.** 아래 accessor·스코프·캐시 컬럼만 쓴다. 규칙을 다 알고 손으로 재현해도 대수가 어긋난 실례가 있다(16대 → 17대·21대).

### 1. 한 글자 차이인데 뜻이 다른 세 합계 — 서로 대신 쓰지 않는다
| 이름 | 식 | 뜻 | 단일 출처 |
|---|---|---|---|
| **총판매가** | 판매가 + 운임비 + 기타판매비용 + 커미션 + AL − TAX D/C | 바이어에게 **받을 돈**(미수의 분모) | `Vehicle::sale_total_amount` |
| **정산 기준액** | 판매가 + 커미션 + AL − TAX D/C | 담당자 **마진** 계산(돈 ①) | `Settlement::sales_amount_krw`(× 정산환율) |
| **면장 기준액** | 총판매가 − 기타판매비용 | 세관에 신고하는 **물건 값**(운임비는 CIF 라 남는다) | `Vehicle::declaration_base_amount` |

- 운임비·기타판매비용은 회사가 대신 치르고 되받는 돈이라 **마진이 아니다**. B/L 재발급비 같은 뒤늦은 비용은 `sale_other_costs` 에 넣는다 → 받을 돈만 늘고 정산·면장은 안 움직인다.
- 면장금액(`export_declaration_amount`)은 저장 때 면장 기준액을 **비었을 때만** 채운다(사람이 넣은 CIF/FOB 값 보존). 정산에 안 쓰인다.

### 2. 판매 미수 (`Vehicle::sale_unpaid_amount` — 그 차 통화 그대로)
```
받은 돈 = 확정된(confirmed_at 있음) 판매 입금 줄 합 — 종류(계약금·중도금·선수금·수수료·잔금) 무관
        + 채권관리 회수 기록 합 — 단, 미러 방식 4종은 제외
        + 적립금 사용(savings_used)
미수    = 총판매가 − 받은 돈          (0 초과 1 미만이면 0 으로 — 외화 소수점 잔차. 음수 = 과입금은 그대로 둔다)
미수율  = 미수 ÷ 총판매가 (0~1, 총판매가 ≤ 0 이면 null)      ← Vehicle::unpaid_ratio
```
- 🚨 **확정 안 된 입금 줄은 안 센다.** 「입력했는데 미수가 그대로」의 1순위.
- 🚨 **미러 방식 4종**(`Vehicle::MIRRORED_RECEIVABLE_METHODS` = `deposit`·`savings`·`misc_loss`·`company_income`)은 다른 곳에 이미 잡힌 돈의 **거울 줄**이다(입금 줄·적립금 사용·과입금 정리). 회수 기록에서 이걸 또 빼면 이중 차감이다.
- **원화 환산 미수** = 캐시 컬럼 `sale_unpaid_amount_krw_cache`(저장 때 갱신, 판매환율 기준). 환율이 없는 외화 차는 `null` — 「환율 미입력」으로 따로 다룬다. KPI·채권관리·대시보드 합계는 이 컬럼을 더한다.
- **집계 미수율**(담당자별·바이어별) = Σ원화 미수 ÷ Σ(총판매가 × 판매환율). 분모에 운임비 등 부대비용이 **들어가야** 분자와 맞는다(`Vehicle::aggregateSaleTotalKrw`). 환율 없는 외화 차는 분자·분모 둘 다 뺀다.
- **실입금 원화**(`sale_received_krw_accumulated` — 환차 계산의 기준) = 확정 입금 줄 × 그 줄의 환율(없으면 판매환율) + 회수 기록(미러 제외) × 판매환율 + 적립금 사용 × 판매환율.

### 3. 매입 미지급 (`Vehicle::purchase_unpaid_amount`)
```
총매입액 = 매입가 + 매도비                                   ← purchase_total_amount
지급액   = 매입 지급 줄 중 「확정됨」 그리고 「지급일 ≤ 오늘」인 것의 합 — 종류(계약금·잔금·매도비) 무관
미지급   = 총매입액 − 지급액
```
- 🚨 **지급일이 미래인 줄·확정 안 된 줄은 안 센다.** SQL 짝 = `Vehicle::purchaseUnpaidRawExpr()`.
- 미지급 ≤ 0 이면 재고로 들어온다(입고일 = 마지막 확정 지급일). 미지급 > 0 이면 재고관리 「지급대기」.

### 4. 「떠난 차」 판정 — 선적 전 미수와 선적 후 미수를 가른다
```
떠났다(departed) = 출고일 있음 | B/L 파일 있음 | B/L 발행일 ≤ 오늘 | 선적일 ≤ 오늘
```
- 단일 출처 `Vehicle::scopeDeparted()` / `scopeNotDeparted()` / `isDeparted()`. 🚫 조건을 옮겨 적지 않는다(채권 분류가 화면·대시보드·알림톡·포털에 흩어져 있다).
- 날짜는 **과거만**(미래 선적일은 아직 안 떠난 것), 오늘 포함. 🚫 `bl_number`(자유 입력칸)·반입지(`bl_loading_location` — 항구 주차장에 세우려고 먼저 찍는다)로 판정하지 않는다. 반입지는 진행상태 단계에만 쓴다.
- **결제대기(grace)**: 안 떠난 차의 미수는 판매일 + 유예일(`Setting::graceDays()`, 기본 10일) 전까지 채권·선적 전 미수 알림에서 뺀다. 떠난 차는 유예 없이 바로 채권.
- ⚠️ **매입 등록 락의 「선적 전」은 이 판정이 아니라 출고일 하나만 본다**(락 절 참조) — 일부러 다른 기준이다.

### 5. 채권 위험 등급 (`receivable_risk` 캐시 — `getReceivableRiskComputedAttribute`, 위에서부터 첫 매칭)
| 등급 | 조건 |
|---|---|
| safe | 미수 0 |
| critical | B/L 이 넘어감 · 또는 배가 도착(ETA 지남) — 받을 수단이 사라졌다 |
| danger | 떠났는데 선적 게이트 미달 · 또는 안 떠났는데 판매 후 N일(`Setting::receivableStaleDays`, 기본 90) |
| grace | 안 떠났고 유예일 이내 |
| caution | 나머지 |
- 캐시 컬럼이라 **규칙을 바꾸면 배포만으로 안 바뀐다** — `vehicles:rebuild-caches`(야간 05:00 자동, 급하면 수동). 시간 경과에 따른 등급 변화도 야간 재계산으로 반영된다.
- 게이트 임계는 바이어별 재정의를 따른다(`LockThresholdResolver`). 알림톡은 등급을 안 쓰고 선적 전/후 분류만 쓴다.

### 6. 정산과의 연결
- 정산 행은 **미수가 0 이 되는 계기**(입금 줄 저장·거래완료 진입·인코텀즈/운임 변경·채권관리에서 털기)에 만들어진다. 「조건은 다 맞는데 정산이 없다」면 그 계기가 울렸는지부터 본다(raw update·일괄 경로는 안 울린다).
- 채권관리에서 「기타」·현금·상계로 털어도 판매 입금 줄은 안 생긴다(거울 줄이 생기는 것은 「입금」 한 종류뿐).
