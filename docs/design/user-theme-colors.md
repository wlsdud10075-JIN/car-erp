# 사용자 테마(색상 꾸미기) — 기획

> 상태: **기획만**(jin 2026-11-13). 착수 = 주말·여유 시간. 코드·마이그레이션 없음.
> 한 줄: 사용자가 ERP 색을 취향대로 꾸미고, 잘 만든 테마는 업무관리자 이상이 프리셋으로 올려 다른 사람도 한 번에 적용한다.

| 1 | 자유 색상 | 팔레트 제한 없음. 단 **의미색은 잠근다**(§3) |

## 2. 바꿀 수 있는 색 (테마 토큰)

| 묶음 | 토큰 | 지금 | 따라오는 곳 |
|---|---|---|---|
| 사이드바 | 배경 · 글자 · 활성 글자 · 활성 배경 | `app.css:36-39` 변수 | 사이드바 전체 |
| 강조색 | 기본 · hover · 연한 배경 · 진한 글자 | `app.css:30-34` 변수 | `.btn-primary` · 활성 탭 · 건수 pill · 입력 포커스 · 링크 + 뷰 82곳 |
| 바탕(B) | 페이지 배경 · 카드 배경 · 테두리 · 표 헤더 · 행 hover · 본문 글자 · 흐린 글자 | 흰색·회색 클래스 직접 | 전 화면 — **변수화 필요** |

- 사용자가 고르는 것은 **대표색 5~6개**(사이드바 배경 · 강조색 · 페이지 배경 · 카드 배경 · 테두리 · 본문 글자). hover·연한 배경·활성 배경 같은 파생색은 **자동 계산**한다(칸이 많으면 아무도 안 꾸민다).
- 색 위에 올라가는 글자(버튼 글자·사이드바 글자)는 **흰색/검정 중 대비가 높은 쪽을 자동 선택**. 저장 차단은 하지 않는다.
- 본문 글자 ↔ 페이지·카드 배경만은 대비 미달이면 저장 화면에 경고(읽을 수 없는 화면 방지). 「기본으로 되돌리기」는 늘 보인다.

## 3. 잠그는 색 (의미색 — 누구 화면에서나 같다)

- 진행상태 뱃지 5그룹(매입 파랑 · 판매 보라 · 선적 주황 · 통관 초록 · 완료 회색)
- 입금 상태 · 정산 상태 · 채권 위험도 · 운항 뱃지
- 할일 dot(긴급도) · urgent 카운트 뱃지
- 필터·필터축 강조: 진행상태 pill 의 「이것만」(보라)·「제외」(빨강+취소선), 필터칩 선택 표시
- 필수 입력칸 · 잠긴 입력칸 · 오류/경고/성공 배너
- 미납 게이지 · 대시보드 차트 색

> 이유: 「빨간 것부터 처리」「보라색이 판매」 같은 말이 사람마다 달라지면 안 된다. 가이드·카드에 색 이름 설명은 현재 0건이지만 구두 소통은 색으로 한다.

## 4. 범위 밖

로그인 밖·외부 화면(전자서명 · 결재 승인 링크 · 자금보고 · 에러 페이지 · 로그인), 서류 xlsx, 알림톡, 다크 모드(설정 화면만 있고 업무 화면 검증 안 됨 — 별도 작업).

## 5. 공유 흐름

1. **내 테마** — 설정 › 화면 꾸미기. 색을 고르면 그 자리에서 미리보기, 저장해야 반영.
2. **프리셋 등록** — 업무관리자 이상이 자기 테마 또는 팀원이 「추천 올리기」한 테마를 이름 붙여 회사 프리셋으로 등록·삭제.
3. **적용** — 누구나 프리셋 목록에서 한 번 눌러 적용. 적용 뒤 내 취향대로 더 고쳐도 된다(복사본).
4. **회사 기본** — 시스템 관리자가 프리셋 하나를 회사 기본으로 지정. 내 테마가 없는 사람에게만 적용.

우선순위: 내 테마 > 회사 기본 > 코드 기본(현행 보라).

## 6. 구조

- **저장** — 테이블 `ui_themes`(id · user_id nullable · name · tokens JSON · is_preset · submitted_at · created_by) + `users.ui_theme_id`(쓰는 테마) + 설정 `default_ui_theme_id`. 🚫 `settings.value` 에 JSON 넣지 말 것(§8 #51).
- **적용** — 레이아웃 `<head>` 에 `:root{--color-…}` 한 블록 주입. 🚫 동적 Tailwind 클래스 금지(빌드 CSS 에 없다, §8 #50).
- **검증** — 서버에서 토큰 키 화이트리스트 + 값 `#rrggbb` 정규식만. 남의 입력이 내 화면 style 로 들어오는 경로다.
- **감사** — 프리셋 등록·삭제·회사 기본 지정은 감사로그(사전 라벨 같이, §8 #41).

## 7. 단계

| 단계 | 내용 | 가늠 |
|---|---|---|
| 0 | **의미색을 강조색에서 떼기** — `.badge-purple`(`app.css:257`)·사이드바 활성 rgba(`:37`)가 강조색에 묶여 있다. 의미색 전용 변수로 분리. 화면 변화 0 이어야 한다 | 반나절 |
| 1 | **보라 직접 클래스 분류** — violet/purple/indigo 최대 322곳(29파일, 차량관리 103)을 「장식 → 강조색 변수」 「의미 → 그대로」로 가른다 | 2~3일 |
| 2 | **바탕 변수화(B)** — 페이지·카드·테두리·표 헤더·hover 를 변수로. 공용 유틸(`.card`·`.input-base` 등) 먼저, 뷰의 `bg-white`·`border-gray-200` 은 화면 묶음별로 | 1주 안팎 |
| 3 | **내 테마** — 테이블·설정 화면·미리보기·주입 | 1~2일 |
| 4 | **프리셋·회사 기본** — 추천 올리기·등록·적용·기본 지정 | 1~2일 |

- 0~2 는 **기본 테마에서 픽셀이 안 바뀌어야** 한다 → 주요 화면 스크린샷 전후 비교(Playwright)로 확인. 0·1 만 배포해도 사용자에게 보이는 변화는 없다.
- 2 가 제일 크고 위험하다. 3·4 를 A 토큰만으로 먼저 열고 2 를 화면 묶음별로 뒤따라 붙이는 순서도 가능.

## 8. 착수 때 정할 것

- 진행상태 pill 「이것만」 보라 = 잠금으로 적었다. 강조색을 바꾸면 버튼과 pill 색이 달라지는데 괜찮은지 화면으로 확인.
- 파생색 계산식(연한 배경·hover) — 밝은 강조색/어두운 강조색 양쪽 표본으로 확인.
- 프리셋 개수 상한, 「추천 올리기」 알림 방식(목록만 vs 알림).
- 가이드·챗봇 카드에 「화면 꾸미기」 추가(같은 커밋).
