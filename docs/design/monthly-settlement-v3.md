## 0. 요청 원문 요약 (jin 2026-10-07)

1. 사내직원도 **프리랜서 공식으로 환산**해 정산씬에 보인다. 환산액에서 급여를 뺀 것이 「급여공제후 마진」.
2. 관리자 대시보드 재무탭 「회사순이익 · 인원별 기여 TOP10」에 **기여 %**. 월정산 알림톡(링크 화면)에도 인원별 기여금·수령액·지분율.
3. 일반사용자 역할에 **검차** · 영업담당자 탭 개명 + 탭(사내직원/프리랜서/검차직원) · 사내직원·검차직원 **급여 항목 11개 + N행** · 매달 빈칸 · 지급합계.
4. 월정산 결재 트리 **업무관리자 → 부장 → 전무 → 대표**(최고관리자 안의 직급).
5. 결재 진행 중 **즉시 수정 → 재결재**(대표가 「누구 더 줘라/빼라」 → 업무관리자 반영).
6. 라벨 「월배치」 → **「월정산」**.

## 1. 확인된 사실 (2026-10-07 실측)

- **반려하면 정산이 배치에서 풀린다**(`SettlementPayoutBatch::rejectBy` `:433` → `payout_batch_id=null`). 반려 배치를 펼치면 정산 0건 + 「기본급만」 줄(현재 명부)만 남아 오해를 부른다.
  ssancarerp 9월 배치 #3·#4 가 오늘 반려되어 정확히 이 상태였다(마진율도 안 나옴 — 정산이 없어서).
- heymanerp 9월 배치 #4 = 승인 · 정산 53건 붙어 있음 · 활성 담당자 10명(사내 6·프리 4) **기본급 전원 미입력**.
- 결재 계단 = `User::approvalRank()` — 관리 1 · 업무관리자 2 · 최고관리자(admin) 3 · 시스템관리자(super) 4. 배치 `current_level` 정확 일치로 서명.
- 현재 사내직원 정산 = 건당 10만 / 차등정산(담당자별 on/off). 월배치 총액 = **정산만**(기본급은 표시 전용, 회사이익에 미관여).

## 3. 열린 질문 (4차)

→ 대화로 진행 중. 답이 나면 §2 에 옮긴다.

1. **기여·지분율 기준 확정(M1)** — 시안 카드에서 「급여공제후 마진」(성과)과 「회사 기여」(지분율)가 갈리는 사례를 보고 확정. 이영업 = 마진 +15.7M / 기여 +40.6M, 정신입 = 마진 −1.26M / 기여 +1.13M.
2. **검차직원 등록 경로** — 지금 담당자 행은 User(role 영업)가 있어야만 생긴다(admin/users :204).
   (가) 사내직원관리에서 직접 등록(User 없음 — 「User 가 원본」 규칙의 예외) / (나) 사용자관리에서 role 「검차」 계정 생성, 로그인만 막음(ROLES 에 값 추가 — `canAccessErp` 는 그대로 거부).
3. **「환율차액」 줄에 무엇을 넣나** — 08-06 이후 1차 정산엔 환차가 이미 녹아 있다.
   ① 판매환율 기준 당월 정산 + 환차 몫을 따로 계산(jin 예시와 같은 모양, 새 계산 로직 필요) / ② 당월 정산은 실효환율 그대로(환차 포함) + 「환율차액」= 2차 마감에서 생긴 환차만(`secondaryBreakdown()['fx']`, 이미 있음).
4. **사내직원의 「이월·추가정산」** — 사내직원 실제 정산금은 paid 때 고정이라 2차 이월이 0 이다. 프리랜서 환산 쪽 이월은 「프리랜서였다면 2차 마감에서 받았을 차액」을 가상 계산해 넣는다 — 이 해석이 맞나.
5. 지분율 분모 = 개인 기여 합(공통 인건비 제외), 음수가 있으면 나머지 합이 100% 를 넘는다 — 시안 표기로 괜찮은가.

## 6. 설계 초안 (착수 결정 전 — 바뀔 수 있음)

**데이터**
1. `payroll_entries`(salesman_id · month 'YYYY-MM' · label · amount · sort · is_custom) — 11개 고정 항목 + N행. 월별 빈칸 시작. `base_salary_krw` 는 읽지 않게 한다(값은 비움).
2. `salesmen.type` 에 **검차(inspector)** 추가 — 🚨 enum 이면 모델 상수 + 같은 커밋 ALTER + 정적 가드(§8 #36).
3. `users.approval_title` nullable(부장/전무/대표) — 최고관리자에게만. 사용자관리 권한 select 아래.
4. `settlement_payout_adjustments.kind`(manual · carryover · loss · **incentive**) — 인센티브 N건 = kind=incentive 행.
5. `settlement_payout_batch_steps`(batch_id · seq · title · approver_user_id · status · acted_at · note) — 제출 때 고른 결재선. 사람 없는 직급은 행을 안 만든다(= 건너뜀). v3 배치만 이 표로 돌고, 옛 배치는 `current_level` 그대로.
6. `settlement_payout_batch_changes`(batch_id · user_id · salesman_id · 무엇 · 전 · 후 · 시각) — 노란 표시와 결재 내역의 출처.
7. 배치 박제 `breakdown_snapshot`(json) — 제출·수정 때마다 사람별 계산 결과를 박제. **반려돼도 이걸로 그린다**(정산은 지금처럼 풀어서 새 월정산으로 다시 올릴 수 있게).
8. 앱 내 알림 — `TaskAlarm` 에 user_id·batch 참조를 붙이거나 작은 별도 표.

**계산 단일 출처** — `PersonSettlementBreakdown`(가칭) 하나가 사람 한 명의 「환산 · 이월 · 환차 · 급여 · 정산금 · 인센티브 · 실지급 · 급여공제후 마진 · 회사 기여」를 낸다. 정산관리 카드 · 월정산 · 승인 링크 · 대시보드가 **모두 이것만** 부른다(§8 #44·#45 — 공식 복제 금지).
