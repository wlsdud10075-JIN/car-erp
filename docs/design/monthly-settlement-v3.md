## 0. 요청 원문 요약 (jin 2026-10-07)

1. 사내직원도 **프리랜서 공식으로 환산**해 정산씬에 보인다. 환산액에서 급여를 뺀 것이 「급여공제후 마진」.
2. 관리자 대시보드 재무탭 「회사순이익 · 인원별 기여 TOP10」에 **기여 %**. 월정산 알림톡(링크 화면)에도 인원별 기여금·수령액·지분율.
3. 일반사용자 역할에 **검차** · 영업담당자 탭 개명 + 탭(사내직원/프리랜서/검차직원) · 사내직원·검차직원 **급여 항목 11개 + N행** · 매달 빈칸 · 지급합계.
4. 월정산 결재 트리 **업무관리자 → 부장 → 전무 → 대표**(최고관리자 안의 직급).
5. 결재 진행 중 **즉시 수정 → 재결재**(대표가 「누구 더 줘라/빼라」 → 업무관리자 반영).
6. 라벨 「월배치」 → **「월정산」**.

## 1. 확인된 사실 (2026-10-07 실측)

- **반려하면 정산이 배치에서 풀린다**(`SettlementPayoutBatch::rejectBy` `:433` → `payout_batch_id=null`). 반려 배치를 펼치면 정산 0건 + 「기본급만」 줄(현재 명부)만 남아 오해를 부른다.
  ssancarerp 9월 배치 #3·#4 가 오늘 반려되어 정확히 이 상태였다(마진율도 안 나옴 — 정산이 없어서).
- heymanerp 9월 배치 #4 = 승인 · 정산 53건 붙어 있음 · 활성 담당자 10명(사내 6·프리 4) **기본급 전원 미입력**.
- 결재 계단 = `User::approvalRank()` — 관리 1 · 업무관리자 2 · 최고관리자(admin) 3 · 시스템관리자(super) 4. 배치 `current_level` 정확 일치로 서명.
- 현재 사내직원 정산 = 건당 10만 / 차등정산(담당자별 on/off). 월배치 총액 = **정산만**(기본급은 표시 전용, 회사이익에 미관여).

## 2. 결정 (jin 2026-10-07 1차 문답)

| # | 결정 |
|---|---|
| 적용 시점 | 11/10 지급분부터. 10/10 은 현행 |
| 대상 | ssancar·heyman. karaba 는 표시만 같이 할 수 있으면 |
| 프리랜서 환산 | **지금 프리랜서 공식 그대로**(총마진 × 비율 − 서류비 − 발송비) |
| 추가정산 | 수기 기입 **또는** 2차 마감 이월분 |
| 환율차액 | 1차 정산 뒤 나온 환차. 총액에 녹아 50% 되므로, 한 화면에 보일 때 **보이는 환차를 따로 빼서 표시**하면 계산이 맞는다 |
| 정산금 | 현행 사내직원 정산(건당 10만·차등) 그대로 |
| 추가 인센티브 | 대표가 「누구 더/덜」 → 업무관리자가 즉시 반영 → 재결재. **급여의 「상여」와 다른 것** |
| 표시 | 사내직원 행은 **접기/펼치기**. 접힘 = 급여공제후 마진 / 실지급총액. 펼침 = 계산 단계 전부 |
| 기준 숫자 | **급여공제후 마진 = 프리랜서 환산액(±추가정산·환차) − 실지급액**. 회사가 그렇게 계산해 왔다 |
| 프리랜서의 회사 이익 | 5:5 이므로 프리랜서 몫을 뺀 나머지가 회사 이익 (jin 의견 — §3 Q1 로 정합 확인 중) |
| 마이너스 | **음수 % 그대로 표시** |
| 검차직원 | 로그인 안 함. 보고용 명부 |
| 급여 입력 위치 | **직원 드로어**(재무가 들어와 기입) |
| 지급합계 | 입력 항목의 총계만. 세전/세후 개념 없음 |
| [관리] 제출 | 일단 둔다 |
| 결재 직급 | 사용자관리에서 영업담당자처럼 **직급 지정**(부장/전무/대표) |
| 중간 결재자 권한 | 기존 최고관리자와 동일 + **금액 수정** + 의견. 그룹웨어 전자결재처럼 **한 줄 내역** 남기고 넘김 |
| 수정 후 재결재 | **멈춘 단계부터 이어서**. 바뀐 내역은 **색으로 표시** |
| 알림톡 | **문구 그대로**(BizM 재심사 회피). 카드·기여·지분율은 **링크 화면**에 |
| 반려 | 반려돼도 **내용이 그대로 보여야** 한다(사실 1 의 혼동 방지) |
