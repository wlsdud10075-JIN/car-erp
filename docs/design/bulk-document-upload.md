## 2. 개별형 — 말소증

**대상 = 선택한 차량.** 모달에 그 차량들이 행으로. **행마다 드래그앤드롭.**

- 드롭존 = `x-erp.file-drop` 재사용 → **행별 진행 게이지가 그냥 나온다**
  (업로드 이벤트가 `.window` 없이 그 div 스코프라 행 간 간섭 없음 — 컴포넌트 주석에 검증 기록)
- 행 반복이므로 **`wire:key` 필수**
- 파일명 자동매칭 **안 함** — 행별 수동이라 오배정이 원천적으로 없다

**상한 = 30대** — 기존 선적서류와 같은 규칙(`vehicle.max30` 재사용).
근거는 **파일 개수**다: Livewire temp × N + S3 왕복 × N + 사람이 N개를 정확히 배정해야 한다.
초과 시 **기존 UI 그대로** — 경고 문구 + 버튼 비활성(모달이 안 열린다).

## 3. 공유형 — 수출신고서 · 체크빌 · B/L

**대상 = 선택한 차량 전체.** 파일 1개가 각 차량에 들어간다.
**상한 없음** — 파일이 1개라 개별형의 근거(파일 개수)가 없다. 실측 B/L 최대 25대.

**형태**: 상단 **드롭존 1개** + 선택 차량 목록(읽기 전용) + **대상 건수 큼직하게**.

### 🚦 안전장치 = 구성 검사 (대상을 다시 고르지 않는다)

파일을 붙이기 전에 **대상 안에서 그 서류의 번호가 몇 종인지** 센다.

| 올리는 서류 | 세는 컬럼 |
|---|---|
| 수출신고서 | `export_declaration_number` |
| B/L | `bl_number` |
| 체크빌 | §6 미결 |

- **1종 → 조용히 통과.** 경고가 안 뜬다.
- **2종 이상 → 멈추고 분포를 보여준다.** 사람이 「그래도 진행」을 눌러야 붙는다.

```
⚠️ 대상 12대에 수출신고번호가 4종 섞여 있습니다.
   41-01-24-0771234  4대
   41-01-24-0771235  4대
   ...
   면장은 신고번호마다 다릅니다. 신고번호로 다시 검색하는 것을 권합니다.
   [ 취소 ]  [ 그래도 진행 ]
```

🔑 **정상 경로에선 경고가 안 뜬다.** 수출신고번호로 검색해 면장을 올리면 1종이라 그냥 통과한다.
선박명으로 검색해 면장을 올릴 때만 멈춘다. **마찰이 잘못된 조합에만 붙는다.**

이 패턴은 새로 만드는 게 아니다 — 선적일 일괄의 **선박명 덮어쓰기 확인**
(`BulkVehicleShippingDateService::vesselBreakdown` / `distinctCount`)과 같은 구조다.

### 🚦 안전장치 ② 「빠짐」 — 선택이 묶음의 일부일 때

선택한 번호를 가진 차량이 **선택 밖에도 있으면** 알려준다.

```
ℹ️ 이 B/L 번호(KMTC-2409881)의 차량 5대가 선택에 빠져 있습니다.
   [ 5대도 함께 포함 ]  ← 기본 켬
```

⇒ 25대짜리 묶음에서 20대만 골라도 **나머지 5대가 서류 없이 남지 않는다.**
🚫 몰래 포함시키지 않는다 — 체크는 켜져 있되 **차량번호를 다 보여주고** 사람이 끌 수 있다.

전례 = `selectedBundle()`(`:282`) — 선택 차량이 한 배치에 속하는지 판정하는 같은 모양의 함수가 이미 있다.

### 왜 이 검사가 필요한가 — 실측 근거

heymanerp 선적요청 배치 44개 중 **3개는 배치 안에서 번호가 갈린다.**
특히 `1911a06f` = **차량 4대에 수출신고번호 4종**(차마다 면장이 다름).
여기에 면장 1장을 붙이면 **3대가 틀린 세관 서류를 갖는다.**

| | 번호 종류 | 평균 | 최대 | 1대짜리 | 2대 이상 |
|---|---|---|---|---|---|
| `bl_number` | 42 | 3.3대 | **25대** | 18 | **24** |
| `export_declaration_number` | 69 | 2.2대 | 6대 | 37 | **32** |

→ 「한 파일이 여러 대를 덮는다」가 기본이고(2대 이상이 과반), **예외가 실재한다.**

## 4. 두 모드 공통

### 이미 파일이 있는 차량 (jin 승인)
**회색 + 비활성.** 보이긴 하지만 누를 수 없다. 교체하려면 그 행의 **[교체] 체크를 따로** 켜야 한다.
공유형은 대상 전체에 대해 **[기존 파일 있는 N대도 교체]** 체크 하나로 처리한다.

### 「어차피 또 나오지 않나?」 (jin 질문) — v4 에서 대부분 해소
대상이 **고른 것**이라, 업로드 후 `clearShipDocSelection()` 하면 칩이 비워지고 다음 묶음을 담으면 된다.
목록에 그 차가 다시 보이는 건 이제 상관없다 — **목록이 아니라 선택이 대상**이기 때문이다.
그래도 남는 도움 둘:
1. 위의 **회색 + 비활성**(같은 차를 또 담았을 때)
2. **「아직 안 올린 것」 필터가 이미 있다** — `action=clearance_needed`(판매완납 + 수출신고서 없음) ·
   `action=shipping_needed`(신고서 있음 + B/L 없음). 이 필터로 들어오면 업로드한 차는 **목록에서 빠지고**
   다음 30대가 올라온다 → **페이지 1만 반복**하면 된다.
   ⚠️ **말소증·체크빌은 대응 action 이 없다.** 필요하면 한 줄 추가(지금 스코프 아님).

### 대상은 서버에서 다시 인가
`shipDocIds` 는 **클라이언트가 조작 가능한 public 프로퍼티**다(SKILLS §8 #26).
ID 목록 자체는 사람이 고른 것이라 그대로 쓰되, **차량별 `canScopeVehicle` 재인가**는 반드시 한다.
스코프 밖은 `skipped[]` 로 리포트.

### 저장
```php
$newPath = $file->store("vehicles/{$id}", config('filesystems.vehicle_docs_disk'));
if (! $newPath) { throw new \App\Exceptions\FileStoreFailedException($col); }
```
🚨 `store()` 는 실패해도 **예외가 아니라 `false`** 다(SKILLS #47). 안 보면 그 `false` 가 컬럼에 들어가고

⚠️ 공유형은 **파일 1개를 N번 복사**한다 — 매 복사마다 반환값을 검사한다.

## 6. ✅ 확정 사항 (jin 2026-09-04)

### 체크빌 = 구성 검사 **없음**
jin: *"a, b 형식으로 검색해서 나오는 묶음은 (사용자가) 알아. 그런 검색에 넣을 거니까. B/L 번호가 없어도 상관없어."*
⇒ 체크빌은 **선박명·컨테이너 접두어 검색으로 사람이 이미 묶는다.** 번호 대조를 하지 않는다.
대상 건수만 크게 보여주고 확인 1단계.
(수출신고서·B/L 은 번호가 명확하므로 §3 의 섞임·빠짐 검사를 **유지**한다.)

### 버튼 권한 = 단건 화면과 동일 (jin 승인)
*"한 대씩은 못 올리는데 일괄로는 올려진다"* 는 구멍을 만들지 않는다.

| 서류 | 권한 | 실제로 보이는 사람 |
|---|---|---|
| **말소증** | `canHandleDeregistration()` | 최고관리자·업무관리자 + **영업 · 수출통관 · 관리** (재무 ✕) |
| **수출신고서 · 체크빌 · B/L** | `canAccessClearance()` | 최고관리자·업무관리자 + **수출통관 · 관리** (영업·재무 ✕) |

- **영업** = 말소증 일괄만 보임
- **수출통관 · 관리** = 4종 전부
- **재무** = 아무것도 안 보임

## 7. 착수 순서 (제안)

전부 진행하되 위험 낮은 것부터 골격을 검증한다.

| 단계 | 대상 | 왜 |
|---|---|---|
| **0** | 통합검색에 `bl_number` 추가 + placeholder 정정·`title` 호버 | §1 선행 조건 |
| **1** | **체크빌** (공유형) | cascade 무관 · 게이트 없음 — 모드 B 골격 검증 |
| **2** | **수출신고서** (공유형) | 같은 골격 + 진행상태 파급 고지 |
| **3** | **말소증** (개별형) | 행별 드롭존 N개 — 화면이 제일 무겁다 |
| **4** | **B/L** (공유형) | 게이트 + 거래완료·출고일 연쇄. 마지막 |

각 단계마다 해당 컬럼을 `AUDITED_COLUMNS` 에 같이 추가.
