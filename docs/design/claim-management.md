## 1. 실무 흐름 (실물 서류 2종 실측)

바탕화면 실물 2건을 확인해 도출. 클레임은 **판정 → 지급** 2단계로 굴러간다.

### ① CLAIM REPORT (docx) — 판정 문서

`CLAIM DISCOVERY SPORT SALCA2BN3HH682215.docx` 실측 구조:

| 섹션 | 실제 값 |
|---|---|
| 바이어 | VILLA KOHA · SALES AGENT MUSA · 총구매 **60대** / 1년 **30대** / 1년 클레임 **1건** / PRIORITY **HIGH** |
| 차량 | DISCOVERY SPORT + VIN · 169,516km · FOB €4,677 · **PROFIT(4.5%) 383,259원** |
| 검수 | `Neither buyer nor sales agent were able to provide the inspection report video or documents` |
| 사유 | oil pan 다중 누유 + injectors·transmission 불량 |
| 증빙 | 정비소 영상 + 사진 + 인보이스 (**VERIFIED**) |
| 금액 | **청구 €1,500 → REFUNDABLE 33.33% → 확정 €500** |
| 결과 | `ACCEPTED` · `COMPENSATION TYPE = NEXT SHIPPING UNPAIDMENT` |
| 결재 | CLAIM MANAGER(LORENA LEE) → SALES MANAGER(MUSA) → **REVIEWED BY CEO** |

문서 NOTES 에 "그동안의 보상 요청은 전부 거절해 왔다"가 명시 — **기각 케이스가 실재**한다.

통화 체크박스(USD/EUR/GBP/KRW), 차량 `07버5628` + 모델 + VIN, 선적일, 판매금액 `FOB 4667`,
내용 `Injectors, Mission is also broken but they couldn't take the videos. INVOICE 1500유로 500유로 보상 협의`, 증빙자료.

## 3. 차감 경로 — 소급 없음, 단일 경로

```
클레임 인보이스 도착 → 재무·관리 기입(확정 보상액 포함) → 미차감 상태로 대기
        ↓
다음 지급배치 제출(SettlementPayoutBatch::submitForMonth) 시 미차감분을 담당자별로 흡수
        ↓
SettlementPayoutAdjustment 음수 조정 생성(claim 연결) → 배치 총액 차감
        ↓
클레임에 deducted_batch_id 기록 = 이중 차감 불가
```

- **차량 정산(Settlement)은 건드리지 않는다.** 클레임은 대개 거래완료(B/L) 후 도착 → 그 정산은 이미
  `paid` → `closed`(회계 잠금)이고, post-close 재조정은 **record-only**(지급 재정산 없음)라 소급이 불가능하다.
- 이월(carryover)이 `Settlement::creating` 에서 미적용분을 흡수하는 것과 **같은 검증된 패턴**을 쓴다.
- 🚫 **클레임 금액을 `cost_extra1/2` 등 차량 비용 컬럼에 넣지 말 것** — `cost_total` → 마진 → 정산액
  경로라, 마감된 정산의 *화면 마진만* 조용히 바뀌고 실지급은 안 바뀐다. `BulkVehicleCostService` 도 closed 는 skip 한다.
- ⚠️ 담당자의 그 달 지급액보다 클레임이 크면 마이너스 지급이 된다 → **초과 경고를 띄우고 재무가 조정
  금액을 줄여 잔액을 다음 달로** 넘기게 한다(자동 분할 안 함).

## 10. board 클레임 미러 (2026-11-11 jin · board-96 세션 협의 — 정본)

**jin 결정**
- ERP 는 **클레임 확정 금액 하나만** 받는다(board 의 청구액·영업 제시액·담당자 제안액 3종은 board 쪽 판정 자료).
- 바이어 드로어에 **「클레임」 탭 신설** — 적립금과 **별도**. 목적 = 바이어별 클레임 **횟수·내용·금액·타당성**을 지표로 쓰기. board 가 세는 클레임 횟수도 받는다.
- 보내는 시점 = board 결재선 최종 승인 뒤 클레임 담당자가 [ERP 로 보내기](자동 전송 없음). 금액을 차량에 쓰는 장면은 나중에 ERP 에서 따로 정한다.

**받는 스펙(초안 — board-96 에 보냄, 확정 전)**
- `POST /api/internal/board/claims` — 연동 B 와 같은 HMAC·멱등. 키 = (회사 인스턴스, `board_claim_id`). 같은 키 재전송 = 갱신(회차 `revision` 이 커질 때만).
- 본문: `board_claim_id, revision, vehicle_id, buyer_id(nullable), buyer_name, vehicle_number, vin, confirmed_amount, currency, compensation_type(refund|credit), result(accepted|declined), result_reason, approved_at, approved_by_name, handler_name, salesman_email, buyer_claim_count(board 가 센 그 바이어의 누적 클레임 수), board_url`.
- 응답 `{erp_claim_id, status}`. 바이어를 못 정하면(본문 buyer_id 없음 + 그 차에도 바이어 없음) **422 「ERP 에서 이 차의 바이어를 먼저 정해 주세요」**.
- 저장 = `vehicle_claims`(§4 스키마에서 금액은 `confirmed_amount` 한 칸 + `source='board'`·`board_claim_id` unique·`revision`·`board_buyer_claim_count`). 바이어 탭은 buyer_id 로 모아 보여 준다(목록 · 횟수 · 통화별 확정 금액 합 · 결과 · 사유).
- 🚫 적립금(SavingsStatus)·미수·정산에는 손대지 않는다(기록만). 차량에 쓰는 기능·담당자 부담 차감(§3)은 다음 단계.

발단 = ssancarboard 에서 첫 실건(EUR 400)이 넘어왔다. §10 의 「금액을 차량에 쓰는 장면은 나중에」가 이것이다. §6 미결(바이어 보상 방식)은 **「다음 차 값에서 깎는다」** 로 닫는다 — jin «그 바이어가 다음 차량 입금 때 400유로 빼고 입금한다 … 우리 쪽에서 털어야 한다». 해외 송금 보상은 거의 없어 나중에 정한다.

**jin 결정**
- **입력은 차량 판매탭 한 곳** — 적립금 칸 옆 「클레임 누적금」(보기)·「클레임 사용」(이 차에 쓴 **합계**, 적립금 칸처럼 더하는 칸이 아니다). 저장하면 채권관리에 **상계 줄**이 자동으로 생긴다(`receivable_histories.source = 'claim'`). 🚫 회수 방법(enum)을 새로 만들지 않는다 — 미수 공식이 안 바뀐다.
- 누적금 = 그 바이어의 **인정된 클레임 전부**(환불·적립 구분 없음) − 사용분, **통화별**. 한도 = 누적금 그리고 **그 차의 남은 미수**(넘기면 과입금이 돼 「과입금 → 적립금·회사이익」으로 클레임이 수익이 된다). 일부 사용 가능, 오래된 클레임부터(결재일 → 받은 날 → id).
- **부담 = 회사.** 상계 줄은 판매환율로 「받은 것」이라 마진·담당자 지급·`company_net` 이 안 움직인다 — **ERP 어디에도 손실로 표시되지 않는다**(클레임 기록과 상계 줄로만 남는다). §2 의 「전액 담당자 부담 · 그 달 정산 차감」(§3)은 이번에 만들지 않는다.
- **정산이 마감된 차도 미수가 있으면 쓴다**(jin «이미 정산 다 됐는데 미수는 없애야 되잖아») — 차량 칸이 아니라 회수 줄이라 마감 잠금에 안 걸린다.
- 입력 권한 = 판매탭을 저장할 수 있는 사람. 감사 = `claim_used` + 회수 줄 감사(PaymentAudit).
- **채권관리**: 그 줄에 「클레임」 뱃지, 수정·삭제 대신 「판매탭에서 수정 →」(모델 가드 — 서비스 밖에서 못 고친다). 그리고 **채권관리 → 그 차 판매탭으로 가는 다리**(`?openVehicle=ID&openTab=sale`, jin «채권관리에서 그 차량 내용으로 바로 갈 수가 없다»).
- **바이어 목록** 「클레임 N건」 뱃지 + 필터칩 = 인정됐고 쓸 돈이 남은 건수(`VehicleClaim::scopeOpen`). 다 쓰면 사라진다. 바이어 탭을 여는 모두에게, 0건이면 칩 숨김, 칩 = 뱃지와 같은 모양.
- 클레임을 쓴 차는 바이어·통화를 바꿀 수 없다(먼저 0 으로 되돌린다).
- board 가 뒤늦게 클레임을 줄이거나 기각으로 바꿔도 수신은 실패하지 않는다 — 그 건의 남은 돈을 0 으로 치고, 이미 쓴 것은 그대로 둔다(사람이 판매탭에서 줄인다).

**알고 둔 것**
- 같은 저장에서 입금 줄과 클레임 사용을 함께 넣으면, 클레임 한도는 저장 **전** 미수로 본다(둘을 합쳐 과입금이 될 수 있다 — 과입금 표시가 뜬다).
- 차의 바이어가 클레임의 바이어와 같아야 한다(바이어 단위 누적금). 컨사이니는 보지 않는다.
- 미룬 것: 해외 송금 보상 · 담당자 부담 차감(§3) · 클레임을 손실로 집계하는 화면.
