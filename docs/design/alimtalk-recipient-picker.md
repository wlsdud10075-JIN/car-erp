## 0. 한 줄 요약

**시간대 × 수신자는 이미 완전히 된다.** 없는 것은 **「계약금이냐 매입잔금이냐」로 갈리지 않는 것** 하나뿐.
여기에 ①규칙 줄마다 **대상 신호 체크박스**와 ②수신자를 **역할별 접이식 목록에서 사람으로 고르는 피커**를 붙인다.

## 1. 조사로 확인된 사실 (2026-09-12 실측)

### 1-1. 현재 데이터 흐름

1. board → `POST /api/internal/board-requests` (**type 스칼라 1개 + 차량 N대**),
   `in:BoardRequest::TYPES` 검증 (`app/Http/Controllers/Api/Internal/BoardRequestController.php:64`)
2. 트랜잭션 후 `notifyCreated($data['type'], …)` (:160) — **한 호출 = 한 type**
3. `notifyCreated` 안에서 **알림톡 코드 하드코딩** `$code = 'erp_board_request'` (:192)
   ⇒ 신호 3종이 **템플릿 1개를 공유**(§8 #54 의 그 구조)
4. 수신자 = `AlimtalkRecipients::forTimeRules($code)` (:193)
   🔑 **`$type` 이 :185 파라미터로 이미 들어와 있는데 전달되지 않는다**
5. `forTimeRules` (`app/Support/AlimtalkRecipients.php:334`) → `matchingRules` (:360)
   = 지금 시각에 걸리는 **모든 규칙 행의 수신자 합집합**
6. 행 판정 `ruleMatches` (:385): `active` → `days` → `from`/`till` 분 비교(`till < from` = 자정 넘김)
7. 토큰 → 번호 `resolveTarget` (:223) — 역할키면 `groupPhones`(:423), 아니면 문자열을 번호로 사용
8. **매칭 0명이면 `admins()` 강제 폴백** (:347)

### 1-2. 규칙 저장

- 키 = `Setting` `alimtalk_timerules_erp_board_request_{set}`, 값 = JSON 문자열
  (`resources/views/livewire/admin/alimtalk-catalog/index.blade.php:218-221`)
- 행 스키마 = `['to' => '관리,manager', 'days' => [1..5], 'from' => '09:00', 'till' => '17:30']`
- 기본값 `AlimtalkRecipients::DEFAULT_TIME_RULES` (:201-205) — **이미 3구간**:

```
평일 09:00~17:30  →  관리, 업무관리자
평일 17:30~09:00  →  대표
주말 종일          →  대표
```

- `to` 는 **역할키(`BROADCAST_GROUPS` :30-41) + 전화번호 혼합 가능** (`isValidTarget` :214, 숫자 8자리↑)
  ⇒ 「대표 + 지정인원」은 **오늘 당장 화면에서** 된다
- `settings.value` 는 이미 TEXT (`2026_08_11_000003`) — 여유 충분(현재 ~200자)
- 편집 화면 = 기능설정 → 알림톡 안내, **super 전용** (`index.blade.php:30, 100, 170, 187`)

### 1-3. 없는 것 = 신호(type) 축

두 군데가 막는다:
1. 설정 키·`TIME_RULE_CODES`(:192)가 **알림톡 코드 단위**인데 board 3종이 코드 1개를 공유
2. 규칙 행에 **type 필드가 없고**, `forTimeRules`/`matchingRules`/`ruleMatches` 어디에도 type 파라미터가 없음

## 2. 확정 사양 (jin 2026-09-12)

### 2-1. 신호별 수신자

규칙 줄마다 **대상 신호 체크박스**(계약금 / 매입잔금 / 판매대금확인)를 붙인다. 목표 모습:

```
계약금            평일 17:30~09:00  →  대표 + 지정 인원
계약금            주말 종일          →  대표 + 지정 인원
계약금            평일 09:00~17:30  →  관리, 업무관리자      ← 기존 그대로 (jin 확정)
매입잔금          평일 09:00~17:30  →  (지정)
매입잔금          평일 17:30~09:00  →  (지정)
매입잔금          주말 종일          →  (지정)
판매대금확인      (현행 규칙 그대로)                          ← jin 미언급 = 현상 유지
```

### 2-2. 수신자 = 역할별 접이식 인원 지정

```
▸ ☑ 관리 (3명 전원)                    ← 접힘 = 역할 전체. 새로 들어온 사람도 자동 포함
▾ ☑ 업무관리자 — 2명 지정               ← 펼쳐서 개별 선택 = 고정 명단
     ☑ 김○○   010-1234-5678
     ☐ 이○○   010-2345-6789
     ☑ 박○○   ⚠️ 번호 없음
▸ ☐ 영업 (8명)
▸ ☑ 대표
```

**규칙**: 역할째로 켜면 = **전원(자동 반영)** / 펼쳐서 개별로 고르면 = **그 사람들만(고정 명단)**.
화면이 그 차이를 말로 적는다 — 「관리 전원 (지금 3명, 새로 들어오면 자동)」 /
「업무관리자 중 2명 (새로 들어와도 안 감)」.

**왜 바꾸나** — 지금의 전화번호 손입력은 함정이 둘이다:
1. 퇴사해도 계속 간다(계정을 지워도 규칙의 번호는 남는다)
2. **번호 없는 사람은 조용히 빠진다**(아래 3-1 함정 #1). 화면에 아무 표시가 없다

피커로 바꾸면 둘 다 해소된다 — 계정이 사라지면 자동으로 빠지고, 목록에 `⚠️ 번호 없음`이 보인다.

### 2-3. 수신자 0명 경고

개별 지정한 사람이 퇴사하면 그 구간 수신자가 0명이 될 수 있다.
지금은 **0명이면 대표에게 강제 발송**(:347)되는데, 그 상태를 **화면에 경고로 띄운다**
(「이 구간은 받을 사람이 없습니다 — 대표에게 발송됩니다」).
🚫 폴백 자체는 없애지 않는다(조용히 0명이 되는 것보다 낫다).

## 4. 함정 (전부 실측 확인)

1. 🚨 **이 경로는 `users.phone` 만 읽는다** — `groupPhones`(:423) → `phones()`(:621-626).
   `salesmen.phone` 폴백(`userPhone` :554-558)은 **`scopedForTiered`(:510)에서만** 쓰인다.
   ⇒ 계정에 번호가 없는 사람은 **조용히 빠진다**. 「관리 3명 중 2명만 받는다」가 여기서 난다.
   ⇒ **피커가 `⚠️ 번호 없음`을 그 자리에 보여주면 이 함정이 해소된다.**
2. 🚨 **`active` 필드는 읽히지만 저장되지 않는다** — `ruleMatches`(:387)는 존중하는데
   `saveTimeRules`(:208-213)는 `to/days/from/till` **4개만** 기록한다 = 사실상 죽은 필드.
   **새 `types` 가 정확히 같은 함정에 빠진다** — 화면에선 켜지는데 저장하면 사라지고 예외도 로그도 없다.
3. **`admin` 토큰이 두 뜻** — 규칙 매칭은 `groupQuery`(:446) 생 `permission='admin'`,
   0명 폴백 `admins()`(:562)는 `override('admin')` 설정(`:629-638`)을 먼저 본다 ⇒ 명단이 갈릴 수 있다.
4. **0명이면 대표 강제 발송**(:347) — 「이 시간대엔 아무도 안 받음」을 표현할 방법이 없다(의도 유지 + 경고).
5. **`<input type="time">` 은 `24:00` 을 못 받는다**(§8 #52) — 종일은 `toggleAllDay`(:98-108) 버튼으로만.
   가드 `AlimtalkCatalogTest:39` 가 `value="24:00"` 렌더를 정적 검사한다 ⇒ 시간칸 구조를 건드리면 깨질 수 있다.
6. **자정 넘김 구간의 요일은 「끝나는 쪽」에도 체크가 있어야 한다**(:353-356, `ruleMatches` :398-400).
   기본 야간 행이 월~금 다섯을 다 켠 이유다. **type 별로 행을 쪼개면 이 실수를 행마다 반복할 수 있다** —
   월요일 새벽 02:00 은 「주말」이 아니라 「월요일」이다.
7. **공휴일 = 일요일(7)로 치환**(:363, :379) ⇒ 「주말」 버킷이 공휴일을 자동으로 덮는다.
   별도 「공휴일」 축을 만들면 이중 판정이 된다. (jin 2026-09-12 현행 유지)
8. **수신자 표 셋은 배타** — `erp_board_request` 를 `DEFAULT_ROLES` 에도 넣으면
   `AlimtalkRecipientTableTest::test_no_template_appears_in_two_recipient_tables`(:47-58)가 즉시 빨개진다.
9. **오타는 조용한 사고**(:167-171 주석) — `관리자` 로 적으면 역할키가 아니라 전화번호로 간주된다.
   ⇒ **피커로 바꾸면 이 함정도 사라진다**(손입력 자체가 없어지므로).
10. **미리보기와 발송이 같은 함수를 써야 한다** — `ruleAppliesNow`(:373-374)가 그 목적으로 public 이다.
    `types` 필터를 `ruleMatches` 에 넣으면 자동으로 따라온다. UI 에서 별도 판정을 만들면 갈린다(§8 #67).
11. **편집은 super 전용**(:30, 100, 170, 187). 「지정하는 대로」의 주체는 **jin 본인**이다.
12. **3사 각각 설정해야 한다**(설정 키가 `{set}` 별).
