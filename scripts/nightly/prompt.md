## 재료
`{{INPUT_PATH}}` 를 Read 로 읽어라. 3사(heymanerp·ssancarerp·karabaerp) 서버에서 방금 읽기 전용으로 수집한 것이다: 아침 점검 dry-run(O/X 표) · 오늘·어제 ERROR 로그 · 정기 작업 상태 · board→ERP 감사 JSON.

## 할 일
1. **X 행과 ERROR 만** 다룬다. O 행·정상은 한 줄로 「이상 없음」만.
2. 각 건마다: **무엇이(어느 회사·항목)** → **왜(코드·설정에서 찾은 원인 — 이 폴더 `C:\xampp\htdocs\car-erp` 와 `C:\xampp\htdocs\board` 의 코드를 Grep/Read 로 찾아 `파일:줄` 을 붙인다)** → **어떻게(고칠 방법 초안: 코드 수정인지·운영 데이터인지·실무 절차인지)** → **jin 이 정할 것 한 줄**.
3. 확인한 것과 추정을 구분한다 — 근거 없는 원인은 「추정」이라고 쓴다. 코드에서 못 찾았으면 못 찾았다고 쓴다.
4. 같은 원인의 로그 여러 줄은 한 건으로 묶고 건수만 적는다.
5. 알려진 정상: ssancarerp 「챗봇 자료」는 09-09 부터 의도적으로 꺼져 있다 · board→ERP 「ERP 미도착」 3건(29조0390·68조9249·06머9117)은 09-28 jin 이 「보고만·한 주 관찰」로 결정한 건이라 반복 설명하지 말고 「기존 3건 그대로」 한 줄로.
6. 규칙(CLAUDE.md·SKILLS.md·메모리)에 어긋나는 제안을 하지 않는다. 운영 DB 수정·배포는 항상 jin 승인이라 「승인 뒤」라고 쓴다.
