# scripts/scene/check — 씬 점검(화면 회귀) 1단계 (dev 전용, master 제외)

가이드 씬의 촬영 스크립트(`../cap/`)를 「사진」 대신 **가이드가 인용한 화면 문구 + DB 값** 확인으로 바꾼 것.
정본 = `docs/design/scene-walkthrough.md §7·§8`. 🚫 배포 게이트 아님. ⚠️ **초안 — 아직 한 번도 실행하지 않았다.**

## 실행
```
node scripts/scene/check/run.js                 # 시더 → 5개 씬 → 결과 표 + JSON
node scripts/scene/check/run.js --only=documents
node scripts/scene/check/run.js --no-seed       # 되돌리기 없이(같은 씬을 두 번 돌리면 실패한다 — 정상)
```
- 로컬 8001 이 떠 있어야 한다(jin 이 띄움 · 🚫 `php artisan serve`). 안 떠 있으면 바로 멈춘다.
- `PLAYWRIGHT_CORE` = playwright-core 경로(없으면 scratchpad 기본값) · `SCENE_HEADED=1` = 창 띄우기 · `SCENE_BASE` = 주소.
- 결과 = `storage/logs/scene-check/result-YYYYMMDD-HHmm.json`. 실패가 있으면 exit 1.
- 실패를 보면 §7-1 표로 가른다(버그 / 의도한 변경 → 기대값·가이드 수정 / 스크립트·예시 데이터 문제).

## 되돌리기 (시더)
차량번호(00가1113·1131·1141)·바이어명(GUIDE SAMPLE TRADING)으로 찾고, 그 안에서 **씬이 쓰는 표식**만 지운다.
- 예시 계좌 `예시` 000-000-000001/000002 + 잔액 행 (`cash_snapshots` 는 안 건드림)
- 발송 줄 EE123456789KR · 1234567890 (모델 delete → 발송비 캐시 재계산)
- 채권 입금(비고 「11/14 송금분 일부」) → 잔금 → 배분, 수수료(「중계은행 수수료」), 입금 기재(「11/14 송금 (가이드 예시)」)
- 00가1131·1141 의 선적일·ETA·선박명·신고번호·컨테이너번호 → NULL (+ 진행상태·캐시 재계산)
- 세 차의 편집 잠금
- 예시 데이터가 없으면 **만들지 않고 멈춘다**.

## 막는 것
- 127.0.0.1:47321(실제 카톡 에이전트) 요청 전부 abort.
- 클릭 가드 = wire:click 메서드(`lookupNiceApi`·`openWonbuLookup`·`send*Alimtalk`·`sendPaidNotice`·`sendVehicleMail`·`sendTelegramTest`·`resendRequest`·`sendVerification`) + 라벨(이 PC 연결하기·이 글 열기·지금 읽기·테스트 발송·NICE 조회·원부조회). 브라우저 캡처 리스너 + Livewire 요청 본문 검사, 두 겹.
- 🚫 라벨 「조회」 는 막지 않는다(채권관리 검색 버튼도 「조회」). NICE 는 메서드명으로.
- ⚠️ **서버가 스스로 보내는 알림톡은 못 막는다** — 잔금 확정으로 완납되면 정산이 생기고 `erp_settle_pending` 이 나간다(로컬 BizM = 실발송). buyer-account 가 「2,000 넣어도 미수가 남는다」를 먼저 DB 로 본다.

## 깨지기 쉬운 곳
- 날짜는 PC 시계로 만든다(서버 `config/app.php` timezone = Asia/Seoul 과 같다고 가정 — 2026-11-16 확인).
- 예시 데이터는 촬영 때 **화면으로** 만들었다 — 시더가 없다. 다른 PC 에는 없을 수 있다(그때 시더가 멈춘다).
- 1단계 밖 씬(export-tab 등)도 00가1131·1141 의 신고번호·컨테이너번호를 채운다. 그 씬을 점검에 넣으면 되돌리기 블록을 다시 볼 것.
- bank-balance 의 「노란 안내 사라짐」 = 활성 계좌가 예시 2개뿐일 때만 맞다(로컬 실측 2026-11-16: 예시 2개뿐). 다른 계좌가 있으면 그 단계만 실패한다.
- 「원화 환산」 은 실시간 환율 조회에 달렸다 — 실패 안내도 통과로 친다.
- 토스트는 사라진다 — 동작과 함께 기다린다(`expectAfter`). 고정 `waitForTimeout` 은 촬영 스크립트 값 그대로라 느린 PC 에선 늘려야 할 수 있다.
- shipment-fee 저장 전 확인 모달은 촬영 스크립트의 문구 목록(맞습니다·확인 후 저장·그대로 저장·저장합니다)으로 누른다 — 새 모달이 생기면 저장이 안 되고 토스트 단계에서 실패한다.
- 「통관서류 알람」 떠 있는 판이 목록 체크를 가릴 수 있다(cap/doc_bar.js 가 닫던 것). 1단계 스크립트엔 닫기를 안 넣었다.
- 결과·실패 문구에 본문 덤프·실명을 넣지 않는다(로컬 DB 에 실무자 이름이 있다).
